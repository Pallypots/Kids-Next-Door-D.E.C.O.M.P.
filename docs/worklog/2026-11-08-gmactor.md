# Worklog: the game layer's actor base (2026-11-08)

For the integrator: this holds what belongs in docs/STATE.md, docs/verification.md and docs/portability.md. Subsystem `gm/gmactor`. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

## What a real build does with this

Nothing reaches it yet. No loader makes an actor: the factories are registered in a static list of create functions (head 0x002CD10C) that a data-driven creator walks, and neither that creator nor any file format that names actors is recovered. Called directly, as the host test does, a real build constructs, initializes, shuts down and destroys an actor base completely, and answers the slots recovered here. The first trigger an animation fires on an actor whose slot 27 answers 1 stops with "Gm actor: 0x001616C0, finding an effect, is not recovered": every path of the callback past that test asks either the trigger table or the effects manager first. `test_gmactor` checks that it stops.

## The class and what derives from it

The actor base is `GmAcActor` (RTTI name, matched by depth; see below), built by 0x0014B5D0, vftable 0x0028E4C8, **60 slots, 0x2D8 bytes** (the factories allocate 0x2D8; FaAcLightSourceRegion's first own word is +0x2D8). Its chain, from the hierarchy descriptors of FaAcScalable, FaAcSpawnWave and FaAcLightSourceRegion, is AtEvSubscriber, GmBaObject, GmAcNode, GmAcActor:

## Oracle

`tests/oracle/oracle_gmactor.cpp`, suite `gmactor`. No file loader reaches this code, so the cases are objects built by each side's own constructor, put in chosen states by writing the same values on both sides, and called directly, the original running its own code at its addresses. Compared: return values, every word of the object (vftables paired by class, pointers into the object, into the list-node pools and into per-side fakes made canonical), objects written through pointers, and the log of allocations, frees, heap pushes, raises, fatal messages and calls to doubles with their arguments (strings by content).

**What stands in, on both sides alike, and so is not tested:** every seam above (the original's address and the recovered function are redirected to one double, which logs and answers as the case says); the actor's unrecovered slots 2, 8, 40 and 49 (vftable copies with those slots replaced); GmAcNode's slots 28 and 29 where the actor calls them directly; fakes for the component, its audio, the motions, the scene actor, the attached node, the link and its owner's sockets, the trigger table; `AtSpaceGraph::RemoveAsKind1` (recovered elsewhere, redirected here). The sound manager is real data: one GmAudioData with two banks of notes, searched by the original's code on one side and the recovered search on the other.

Cases: each class constructed and destroyed by each destructor and deleting form (flags 0, 1; arrays with flag 2 for GmBaObject and 3 for the factories' arrays); GmBaObject's slots initialized and not; the node's methods on a node and on an actor; the controller with and without an owner and with 0, 1 or no slots, cleared and destroyed; the node's shutdown over all 32 combinations of link, link owner, material assignment, deletable, scene node; the actor's shutdown and destructor over 256 combinations of component, attached node, scene actor, deletable, +0x218, motions (2 or 3, one null), records (default count or given); reset on dirty memory; records alone; 0 to 3 real items on real lists with three flags; 64 states of the small slots; both factories with counts -1 to 3, no heap, and refused memory; the callback over slot 27, trigger table, its two answers, the effects manager's answer, component (none, without audio, with), the table's note, the actor's bank, the bank GetNoteBank gives, and six trigger names including a nine-character one, then OnLoop; with no actor, node and place combinations with banks in use and not.

Result: `NO DIFFERENCE OBSERVED: 2767 cases; 553616 comparisons, 0 differences`; entries reached 70 / 70; mutants detected 238 / 238. The first mutant run had 16 survivors of 239: 15 were harness gaps, closed by cases (a GmBaObject destroyed uninitialized with words set; up to two animation slots and a blend holding a block, so the order of frees shows; the controller's owner, distinct socket ids, the link's words set, and the node's destructor in the node-shutdown cases; slot 1 replaced to show slot 7 returns Initialize's answer; the banks' maps by name, so FindNote can find; a real item in the list in the actor-shutdown cases; records in the item cases). One, clearing +0x270 after deleting it, is dropped as equivalent: ResetActor clears it before the shutdown returns. `--suite all --no-mutants`: all 38 suites show no difference. ## Quirks kept

* GmBaObject's destructor shuts down only when initialized; its deleting destructor handles arrays of 0x18-byte elements, GmAcNode's does not, GmAcActor's does.
* GmAcNode's shutdown deletes the link but leaves m_link until Reset; it takes the link out of the owner's second list before the first.
* The actor's shutdown re-reads the component after its slot 3 and deletes it without clearing it (ResetActor clears it); likewise the scene actor. It looks "Motion" up in the name map at 0x002CD124 and ignores the answer. It frees the motion array but leaves the pointer for ResetActor.
* ResetActor sets +0x24C to -FLT_MAX.
* Slot 52 converts an unsigned word to float through the signed conversion and adding 2^32 when negative; the float result is the same as a direct unsigned conversion.
* SetUnknown284 stores null for the actor itself.
* OnTrigger makes nine-byte copies of the trigger and bank names it never reads; passes a found table note to a method of the sound manager (0x000B15B0) that returns 0 and ignores it; with no actor, calls FindNote with a null bank name, which crashes when any bank is in use and finds nothing otherwise, so nothing after it in that branch can run (the position, the placing, and a call to an empty method 0x000447F0); posts a note's GameEvent with the actor, or null.
* The two factories are the same code twice, registered as "Rotator" and "Node" of package "GmAcNode"; "Node" is registered with size 0x14C though it makes a 0x2D8 actor.

## Not compared, and why

* Mutants in the no-actor branch past FindNote: unreachable on both sides, as above.
* Zeroing the bank before GetNoteBank: the double writes all eight bytes, as AtCopyName8 does in the other branch; whether the real 0x000A1E10 does is not known.
* AtEvSubscriber's slots: its vftable's extent is not known, so it is not recorded and only its destructor is compared.

## Shared edits and requests

None to shared headers. `include/gm/GmAcActor.h` declares a `GmLinkedListIteratorOf<T>` template of its own, which `include/gm/GmLinkedList.h` names in a comment but does not declare; if it is later wanted there, move it. `GmAcAnimationCallback::m_place` and the callback's no-actor branch take `AtCoordSys`, whose two methods here are seams (0x000332B0, 0x00032EA0): whoever holds AtCoordSys may want them as members.

## My mistakes

* I first put the seams in the same files as their callers; the compiler inlined them, so the oracle's redirects missed them and the first run showed the recovered side's diagnostics. They are now in `GmAcSeams.cpp`.
* I first expected `delete[]` to make the compiler give a class its array-aware deleting destructor; it is `new[]` that does. Until then the host's slot 0 ignored flag 2, and freeing an array from the factory corrupted the heap.
* The original's pool of list nodes is constructed by the game's start-up, which the oracle does not run; the first item cases crashed on the original side until the harness constructs it.
