# Events by name: the .AEE reader, an event's subscriptions and publishing (subsystem `at/aee`), 2026-11-19

For the integrator: this holds what belongs in docs/formats.md, docs/verification.md, docs/STATE.md and docs/startup.md. Reference build knd-xbox-usa-5454008a-v1. Branch from the manifest base (worktree-agent-a7575536780e46e01, 2e2b9ef). State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

**What a green result does not show, first.** Every real `.AEE` file (47 distinct contents) loads through the original's code and the recovered code with the same result, and both sides' events are then subscribed to and published alike. What a handler does when an event fires is not here at all: in the oracle the handlers are the harness's, which log and sometimes subscribe or unsubscribe. The heap is the oracle's double on both sides. The owner the database registers with is the real `AtDataRegistryOwner::AddDatabase` (at/add) on the recovered side and the original's 0x000992D0 on the other, but the owner object itself is built by the harness from recovered constructors. Nothing here runs a `.MNG` file: the dbmanifest oracle and host test still stand a double in for `AtEventDatabase::Load`, by design (see below).

## The format

Text, through the common tokenizer. Three words, ids 0x39 to 0x3B, keyword table 0x002B6848:

```
NameSpace "Level"        the name space the database registers under; none means the owner's plain group
NumSubscribers 140       how many subscriptions all the file's events may hold between them; 100 without it
ShortName[127]           the events' short names, eight characters at most
{
    "Start" ...
}
```

All 47 real files have a NameSpace (Game, Cheat, Arena, Level, music and so on) and a ShortName list; most have NumSubscribers. 1964 events in all, 3950 subscriptions. GAME.AEE and CHEAT.AEE are loaded from AppInit.JAM; each level has DESIGN\LOCATION\<level>\*.AEE and usually an AUDIO\LOCATION\...\*.AEE of "music" events.

## Port adaptations

* A handler in the original is the address of a member function of the subscriber's class, called `__thiscall` with the message (callers pass e.g. 0x00020D40, 0x000E0ED0). Here `AtEventHandler` is a plain function given the subscriber and the message: C++ cannot store a member function of an unknown class in one word, and a port needs no x86 convention. The oracle gives the original side `__thiscall`-shaped handlers and the recovered side plain ones, and compares which handler each subscription holds by identity.
* The subscriptions' block is `count * sizeof(AtEventSubscription)`, which is the original's `count << 4` on x86 (16 bytes); `<< 4` overran the block on x64.
* The events are a real `new[]` through a noexcept placement form (the heap may answer null), because the host compiler emits a real vector deleting destructor (`??_E`) only in a file that both holds the vftable and sees the class's `new[]`; otherwise `??_E` is a weak alias of the scalar one, and the list's `delete[]` freed the wrong address (found as heap corruption in the first oracle run).
* `Load` is alone in `src/at/AtEventLoad.cpp`, so that the dbmanifest oracle and host test, which define their own `Load`, still link the rest of the class.

## Quirks kept

* The first token is taken as a word even at the end of the text, which then asks the tokenizer for one more (a do-while); an empty file reads twice.
* `Read` clears first only when the list holds an array; `Clear` does nothing at all, the name map's Clear included, without one. A file with NumSubscribers and no ShortName keeps its block across reloads and leaks it on the next NumSubscribers.
* A repeated NumSubscribers loses the earlier block; a repeated ShortName loses the earlier events and registers the map again. NameSpace counts only before ShortName.
* `Allocate` frees nothing that was there, makes an array even for a count of 0, and enables every event (flags 2).
* `Subscribe` takes a free subscription before looking: a subscriber already in the list only has its handler and mask replaced and the taken one goes back; with none free, nothing happens, even for one already subscribed.
* `Unsubscribe` matches handler and mask exactly, a null handler or a mask of 0 matching any; it frees only the first match.
* `Publish` tests the flags of the message's event, not its own, and takes the next subscription before calling a handler, so a handler may unsubscribe itself; a subscription added during the call is reached if it is appended after the current one.
* An event's destructor frees its subscriptions by clearing them and leaves its own head as it was.
