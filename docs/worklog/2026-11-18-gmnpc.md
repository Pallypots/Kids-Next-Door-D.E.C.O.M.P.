## What a real build does with this

Still nothing reaches it from data: no creator walks the static list of create functions (FaAcNPC's factory 0x00092A50 is registered three times, GmAcNPC's 0x0014EB70 once). Called directly, a real build constructs, shuts down and destroys a GmAcNPC and a FaAcNPC completely, answers the AI's condition names (slot 60) for everything but the sight conditions, and runs the health levels up to the first level it formats. Reading a record stops first: FaAcNPC's slot 2 and GmAcNPC's slot 15 reach the registry's search 0x000679E0 (a seam on this branch; another agent is recovering it), whatever the record. With that search recovered, the next stops are: "CreateAiActionManager" makes the AI action manager (constructor 0x0017D420, a seam), "Combat" makes FaCmCombat (0x000A3360, a seam), the health levels stop in the passing formatter 0x00072330, and "cNCanSee"/"cFront"/"cNFront" stop in the sight test 0x00130E50. `test_gmnpc` checks that slot 2 stops.

## Quirks kept

* GmAcNPC's shutdown does not ask whether the object is initialized; its slot 15 does not test the record before looking up CreateAiActionManager, and makes another manager over one already there (likewise FaAcNPC's combat object).
* FindValueObject tests neither the registry nor the record; FaAcNPC's slot 2 keeps a range absent from the record and searches ranges without the defaults, but always replaces the level count, defaults included.
* FaAcNPC's reset clears the character's +0x2E4, which the character's shutdown has deleted by then; its slot 4 resets the last health to FLT_MAX.
* Health levels: nothing unless the last value is above zero and health has fallen; a level is crossed when value <= threshold * maximum < last; the search stops at the first level that acts or posts; the last value is replaced on every call that reaches the health stat. The level's name is copied out of the formatter's buffer without a bound. The event object is never destroyed.
* Conditions are eight-byte names, so a longer name matches its first eight characters. "cNCanSee" has no "cCanSee"; "cFront" answers the sight test's own value; "cNTgtAir" and "cTgtAir" answer the base's 0 when the target is not the player; "cShield"/"cNShield" answer the base's 0 without a stats holder; "cAtkRg<c>" compares the range with c - '0' for any character c, signed.
* GmStatInRange: the lower bound open, the upper closed, an unordered comparison false.
* GmNthControlledCharacter reads its count from +0x4C, which is also where it reads the second character, so the list only works with one.
* AtCompareN compares signed characters, unlike strncmp.

## Not compared, and why

* The base's TestCondition always answers 0, so returning it or 0 cannot be told apart (no mutant of that kind is kept).
* The registry's search, the value classes, the AI action manager, FaCmCombat, the events, the formatter and the sight test: seams.
* The x87 precision of the original under the Xbox's control word: the oracle runs both at the host's (53-bit); the range test is written in double accordingly.

## Portability

* +0x17C (`GmAcActor::m_unknown17C`, slot 53 `Unknown17C`) holds an actor pointer (GmAcTargetOf proves it), declared unsigned int. On a 64-bit host it cannot hold a pointer; the recovered code casts through it as the original does. It should be retyped to `GmAcActor*` (a shared change: the gmactor suite has a mutant returning `m_unknown180` from that slot, which would no longer compile). The host test only uses a null target.
* `(signed char)` is explicit where the original sign-extends a name character, for ARM's unsigned char.
