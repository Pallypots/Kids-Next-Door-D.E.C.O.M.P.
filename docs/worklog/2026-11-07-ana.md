## What the green result does not show

* **Binding is not recovered.** 0x00073010, 0x00079040, 0x00079120, 0x00079170, 0x00078EF0, 0x00078FA0, 0x00078AD0 are left. So the unbinding code runs on links the harness binds by hand, the same on both sides, and on fake controllers. No real file reaches it. What real files reach is reading and allocation.
* **The controller is a stand-in.** `AtInputController` is a few fields of a 0x120-byte class; it is not to be constructed.
* **The one real .ANM uses little of the format.** 19 mappers, 312 button map entries and 114 axis maps. Of the optional words it has only `AbstractAxisState`, 66 times. No `NameSpace`, `PhysicalButtonState`, `AbstractPOVState`, `PhysicalPOVAxis`, `AbstractPOVAxis`, no empty list and no copy of a mapper. All of those, and every error path, rest on written text.
* The harness's tokenizers are recovered ones, on both sides, as in the earlier suites; the tok suite is what establishes them.
* AFL and AFX through the file code: a bad word's report comes back in the harness, and the readers loop until a closing brace, so text that never closes one would spin on both sides. Such text is only run where a stopping tokenizer can be passed in, which is ANM and the AFX format reader. **`AtFlashLevel::Load` and `AtFlashTextFormatTable::Read` cannot be given one**, so running out of text inside them is not tested.
* **Not compared, uninitialised stack.** A mapper whose name is not a string: `ExpectName` leaves the name's stack bytes, which differ between the sides, so the slot it hashes to differs. Removed from the written cases, with a comment. `AbstractMapper 5 ""` inside a mapper stays: both sides find nothing and crash.
* **Not run: allocating a router twice.** `Release` leaves the free list's pointers, so the next `Allocate` writes one word into freed memory. Both would do it, on the harness's real heap. That the pointers are kept is compared, by whether they are null.
* `AtFlashTextFormatTable::Read`'s caller 0x00020570 is not recovered, nor the base's 0x000171B0 and 0x000170E0: the oracle calls the original's 0x000171B0 on both sides to make groups for `Clear` to free.

## Quirks of the original, kept

* A `ButtonMap`'s `AbstractPOVState` is lost. `abstractId |= token << 16` uses the token, always the closing brace (6) there, so any POV state gives 0x60000. Read as a slip for the state.
* The state is stored less `POVUp`, and 8 means none was given. No word in the tables comes to 8 that way, so any word given counts as a state, even a bad one, with no report.
* `ButtonMap[0]` and `AxisMap[0]` return before the closing brace, so the mapper's own loop takes that brace as its end, and what follows in the file is misread.
* `CopyFrom` passes the source's already doubled button capacity to `Allocate`, which doubles it: a copy has twice the room.
* `AtInputMapper::Clear` and `AtInputMapperDatabase::Clear` do nothing unless device, or items, is set. `Clear` frees the axis maps by the capacity, the button maps by the pointer.
* `PhysicalPOVAxis` and `AbstractPOVAxis` take `AxisX` or `AxisY`, and `AxisY` sets bit 16 of the abstract id, whichever word it came under.
* `PhysicalButtonState` does not take `ButtonUp` or `ButtonDown`, despite its name and the table: 0x44 and 0x45 are reported as bad. Takes `AxisPositive`, `AxisNegative` and the POV words.
* `AtInputLinkList::Remove` reads the first entry whatever the count, and one past the count, so it finds a link there and takes the count down for it.
* `AtInputRouter::Release` leaves the free list's pointers.
* `AtInputMapperDatabase::m_unknown1C` is only ever cleared.
* `AtFlashLevel::Load`: `HeapSize` is read and then zeroed, so the level never has its own heap, and the `CreateHeapAt` branch is dead. It still asks for a block of 0 bytes. All 2 real files say `HeapSize 0` anyway. +0x330, 20000, is never read here.
* `FontSourceLevel` with neither `Self` nor `All` takes the tokenizer's last integer, even if the token was a string or a word.
* `AtFlashTextFormatTable::ReleaseFormats` destroys through `m_items[0]`, so it takes the first item to be the array, and leaves all alone if that entry is null.
* The name space in an .AFX is read through `ExpectStringCopy`, copied to 8 bytes, and freed.
