# The math, data management, script and kinematics layers (subsystem `at/atlayers`), 2026-11-18

For the integrator: this holds what belongs in docs/startup.md, docs/STATE.md and docs/verification.md. Reference build knd-xbox-usa-5454008a-v1. State of
everything here: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler (blocked, docs/toolchain.md).

**What a green result does not show, first.** The oracle runs each layer's Init, constructor, Shutdown and SetHeaps on objects made by each side's own
constructor, with the virtual slots they call (Shutdown, SetHeaps) replaced by tables that log and run the side's own code. The start-up chain itself, with
these objects running inside App, is exercised only by the host tests (test_app over the real levels directory, test_atap). The nineteen script built-ins
and the script factory's Release are doubles on both sides: start-up only registers the built-ins, and the oracle checks which addresses are registered
under which names, not what the built-ins do.

## Quirks of the original, kept

* AtSmallCSystem::Clear clears the system's own heap global (0x002CF170) along with the system; the host sets it again just after.
* AtScriptHost::Init sets the system's and the factory's heaps to its own heap, overwriting what the layer's SetHeaps set from config +0xC and +0x10:
  those two config fields have no lasting effect at start-up.
* AtSmallCSystem::Register copies the name unbounded into a 0x14-byte field; a longer name runs over the entry's function and context words, written just
  before.
* The kinematics layer sets its heaps twice: its base's Init calls SetHeaps, then its own Init calls it again.
* The kinematics layer raises -4 when its factory cannot be made, then stores the null (the raise is fatal in the game).
* The script layer's running flag is a word of its own (+4) and its Init sets it to 1; the others' flag is the pointer to the layer below.
* The math layer's Shutdown is the same code as AtDataComponent::Reset (folded).
