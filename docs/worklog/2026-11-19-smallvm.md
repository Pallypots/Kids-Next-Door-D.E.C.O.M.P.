# The behaviour scripts' abstract machine (subsystem `at/smallvm`), 2026-11-19

For the integrator: this holds what belongs in docs/STATE.md, docs/verification.md, docs/formats.md and docs/portability.md. Reference build
knd-xbox-usa-5454008a-v1. State of everything here: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

**What a green result does not show, first.** Every built-in the disc's scripts call reaches game code that is not recovered (vState, bAnim,
bProcessEvent and 26 more, registered by game code around 0x000ABA33 that is not recovered either). In the oracle one double stands for all of them on
both sides: it logs its arguments and the strings they address, and answers from a sequence both sides replay. So the oracle shows that the machine runs
the scripts identically and calls the same built-ins with the same arguments in the same order; it shows nothing about what those built-ins do. The
nineteen core and float built-ins (numargs ... floatcmp, 0x0007C800-0x0007CDEF) are still seams that stop; no script on the disc declares them.

## What the scripts are

The three `.ASL` files in DESIGN\BEHAVIOR (BAISHELD 1448 bytes in Aamalgam.JAM, BAIPATHH 5132 in Asticky.JAM, BKID 4820 in Lbkyrd1.JAM; the only
AMX images among the disc's extracted files, by a scan for the magic) are compiled **Small** programs in the AMX format, and the code at
0x0007A7D0-0x0007C7F7 is a Small abstract machine. Evidence, from this executable and these files only:

* 0x0007AB40 refuses a header whose word at +4 is not 0xF1E0 or whose word at +0x0A (the table entry size) is not 0x1C: AMX's magic for 32-bit
  cells and its entry size.
* The interpreter's jump table (0x0007C5B4) covers opcodes 1 to 0x85, and their semantics follow Small's published instruction list in order: PROC 46,
  RET 47, RETN 48, CALL 49, SYSREQ_C 123, FILE 124, LINE 125, SYMBOL 126, SRANGE 127, SWITCH 129, CASETBL 130. The scripts decode cleanly with that list
  (analysis-local/scratch/smallvm/amxdump.py).
* Version: every file says file version 3 and required machine version 1; the header has 16-bit table counts each followed by an unaligned 32-bit offset
  (+0x20 .. +0x3D); the machine has no `hlw` register and no opcode past 133 (no NOP, SYSREQ_D, SYMTAG, BREAK). That is the machine of the Small
  toolkit before 2.x (file version 3); the exact toolkit release is not established.

**Not the published machine unchanged** (the quirks are this game's):

* A built-in is called `function(context, amx, params)`: each native entry carries a context word before the address, which Register fills from the
  context registered with the function (the system registers its own built-ins with itself as context). The shared typedef `AtSmallCNative` changed to
  match.
* Opcodes 131 and 132 (SWAP_PRI/SWAP_ALT in the published list) read and write host variables through the header's fifth table (+0x38/+0x3A, the
  published "tags"), each entry's second word bound by 0x0007B160 to an address from the system's table at +0x3800. The variable is the first argument
  on the stack; the operand is not read.
* Opcode 133 (PUSHADDR in the published list) suspends: the registers, the data and code pointers are kept in the script object (+0x84..+0xA4) and Exec
  returns -1; the next Run resumes there. LINE, while debugging, also suspends when the system's step flag (+0x5B38) is set.
* The interpreter's operand, opcode, native result and debug flag are globals (0x00301B3C, 0x00301B40, 0x00301B38, 0x00301B44); the debug flag is not
  reset by a resume. 0x00301B34 is the little-endian flag, set by Init.

Format, for docs/formats.md: header as `AtAmxHeader` in include/at/AtSmallVm.h; table entries of 0x1C bytes {context or 0, address, name[20]};
publics sorted by name (FindPublic is a binary search); code then data, then heap and stack up to `stp`; jump operands are code offsets, relocated at
load to addresses. Compact encoding (header flag 4) is 7-bit groups read backwards from the end, sign in bit 6 of a cell's first byte.

## Who loads and runs a script

* Load: `GmScriptOwner::Load` (0x00070310; gm/manifest's seam, now recovered) splits the path at its last backslash, pushes the directory onto every file
  system's path and starts the script (0x00070220 -> `AtSmallCSystem::StartScript` 0x00075CB0), which takes a slot of 2000, loads `<name>.ASL`
  (0x000758B0: at most eight characters of the name; a 0x40-byte header read, then `stp` bytes on the system's heap), runs Init (0x0007AB40: checks,
  compact decoding, relocation), registers the built-ins and host variables, and finds the entry public. Callers: the manifest's SmallCScripts items
  (GmScriptItem::Run 0x001B2DD0) and the behaviour charts' loader 0x0019BE60 (through the owner at 0x003B3C60).
* Actor slot 15 (0x0014AE90) does not call the machine itself: it makes the actor's behaviour object from its BChart and, for a BScript, calls that
  object's slot 27 with "Design\Behavior\%s". The behaviour charts (.SSM, read by 0x0019BE60) start their script through the owner above.
* Run: events reach `GmScriptOwner::CallPublic` (0x00070190, from 0x00165470) -> `AtSmallCSystem::CallPublic` (0x00075B20) with copy 1, which runs the
  public on a copy of the script's machine (sharing its memory), through `Run` (0x00075860) and `AtAmxExec` (0x0007B1C0).

## What a real build does now

On a real level, the manifest's SmallCScripts items now load their `.ASL` through the recovered code instead of stopping in a seam. Because the game's
built-ins are not registered by anything recovered, Register then finds each one missing and StartScript fails with 4 (the script is released and Load
returns null); Register's missing-built-in path is the original's (below). Nothing stops with a diagnostic on that path. Run on its own (host test
`test_smallvm <cases dir>`, x64), every public and main of the three disc scripts runs to completion over stand-in built-ins: 3 files, 56 calls.

## Quirks of the original, kept

* Register, on a built-in it cannot find, allocates the format string's length (37 bytes), formats the warning at `block + strlen(name) + 1` (past the
  block's end), tests that pointer for null and frees it. Nothing prints it. Kept as is: a port must decide (the oracle survives it with padded blocks
  and a free that tolerates interior pointers).
* Init lowers the header's own `stp` by a cell and clears that cell; its relocation's result is ignored (Exec then refuses with 22).
* Exec compares the machine's stk (an offset from the data) with the header's stp (an offset from the program) for "stack low"; RETN at the end leaves
  stk where the return put it while RET resets it; STACK and HEAP errors do not reset stk; CASETBL executed does nothing and the next word is taken as an
  opcode; index -2 reads the entry two before the first public; negative addresses pass the memory checks.
* Relocation calls the debug hook for SRANGE only if the last SYMBOL's parameter had no bits above 8.
* SDIV rounds down; shifts by 32 or more wrap as x86 shifts do (the compact decoder too).
* Run always returns 1; after an error the call stays open (flag 2), and the next Run resumes from the last suspension's state.
* StartScript copies a 9-byte name it never uses; a shared script's program is freed with its source; Release resets a null script (crash).
* FindHostVar with count -1 has no end but a match; FindPublic copies each probed name unbounded into 20 bytes.
* The factory's Release resets the script, then destroys it (which resets it again) and frees it.

## Portability (docs/portability.md)

A program's cells hold three kinds of host pointer in the original: relocated jump targets, a native's function and context, a host variable's
address. On a 32-bit build the recovered code stores them as the original does. On a 64-bit build (the only variant): jump operands keep their code
offsets and the interpreter adds the code's address where a target is used; functions, contexts and variable addresses go through a process-wide table
of references (`AtAmxStoreHostRef`/`AtAmxLoadHostRef`). Scripts can read code memory (negative addresses), and would see offsets instead of addresses
there; none on the disc does. `AtSmallCSystem::Run` takes the parameters as a pointer, not varargs (all known callers pass none). Cells are read and
written byte-wise (unaligned addresses are legal).
