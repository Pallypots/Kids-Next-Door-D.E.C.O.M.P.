## Game and port: how they meet

* src/at/AtFatal.cpp is the game's AtFatal and holds nothing else, so a program that defines its own AtFatal never pulls it in from the library.
* It ends in three functions that are not the game's: `AtPlatformLaunchImage` (XLaunchNewImage), `AtLibraryPrint` (printf), `AtLibraryExit` (exit), declared in include/at/AtFatal.h. platform/fatal.cpp supplies them on a host: no dashboard, so the launch returns; the game's message goes to stderr; exit aborts, the host's stop.
* platform/fatal.cpp keeps its stand-in AtFatal ("fatal: %s (%d, %d)", abort) for every program that does not link the game's, which is every test and the oracles that link it, under `#ifndef KND_GAME_FATAL`. A future game program that links the game's AtFatal compiles platform/fatal.cpp with `KND_GAME_FATAL`. **For the integrator:** nothing defines it yet; no game program exists.
* The graphics calls of the screen go through seams that stop with a diagnostic: `AtGr2DRenderer` (slots 3 and 62 named), `AppGraphics::Camera2D` (slot 27), `AtMaterialOwner::Present` (slot 9), `AtMatrixDevice::NewMatrix8` (slot 8), and the images' slots 0 and 3. The oracle and the host test supply them.
* In a real build today: `AtControllerManager::s_ready` is never set (its Init is not recovered), so the rumble part is skipped; `m_dirtyDiskLoader` is set by start-up only past seams that stop first, so the screen is skipped; the program prints and aborts. A real build reaching the screen would stop at the first renderer slot with a diagnostic, which calls AtFatal again, which skips the screen (its latch is set) and leaves.
* test_app and oracle_app supply their own AtFatal and AppUnknown692C::Update; they do not pull these objects in. GmAppHost.cpp's stub for Update is removed, as Update is now recovered.

## Quirks of the original, kept

* **_ftol2 truncates to 64 bits.** A colour component past an int's range keeps the low byte of its 64-bit integer. A plain `(int)` gives 0x80000000; the oracle found it (one difference in 200,000 colour cases, from a huge ratio). Modelled by `Truncate`, a `long long` conversion.
* `AtColorF::Lerp`: the red and green products stay in registers for the sums, blue and alpha are stored and read back, so rounded first.
* `GmRumblePlayback::Intensity` takes the last frame strictly before now, fetches the next and does not use it: no blending.
* A looping playback wraps once per Advance. `Finished` counts a time equal to the length as finished.
* `AtRumblePlayer::Update` asks the device for the controller afresh each time (1 + one per motor); one motor carries both sides' sum; the finished ones go to the last place of the pool of ten, and the whole rest moves down past the count.
* The manager's resume callback is called with the context in ecx and nothing on the stack. **Here a plain function given the context**: the one deliberate change of convention, at a boundary nothing recovered sets.
* `AtImage::Draw` moves on by a strip only after one that showed: a wholly clipped strip leaves the next where it was. Rows begin at strips whose x0 is the first strip's, below the last strip drawn. Draws nothing unless flag 0x10 (kOwnsData in AtImage's enum) is set.
* `AtRect::Clip`: a NaN on a side does not make the rectangle empty; uv's right is done before its left, each in terms of uv's left as it stands.
* The screen draws the pair `2n, 2n+1` of the dirty-disc images, English 0, German 2, French 4, Italian 6, by `AtCompareName8` of the eight-character language: "ITALIANX" is English.
* AtFatal's text buffer is 0x100 bytes and its sprintf can run into the launch data, which has gone by then; the recovered frame keeps that layout.
* AtFatal's second parameter is printed with %s: it is a file name, though the shared declaration has it as int. Every recovered caller passes 0, printed as (null).
