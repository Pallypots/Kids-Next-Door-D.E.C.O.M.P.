# Worklog — dev cycle 16 (2026-11-06): vector math

## Done

* Chose work from the call graph: `analysis-local/scratch/ready.py` lists functions whose callees are all recovered. 2,957 functions and 276 KB qualify today, and the clusters with the most callers came first.
* Recovered 14 functions of `AtVector3`. Oracle: no difference over 44,000,024 comparisons, 14/14 entries, 41/41 mutants; 8 more not distinguished, named in docs/verification.md. The x64 build matches a hash of the original's results for the 11 functions without a sine or cosine.

## Found

* **The main thread's x87 precision is 53 bits**, read from the C library's start-up, a question open since the tokenizer cycle.
* `double` in source for what stays in a register, `float` for what the original spills, reproduces its bits, so this one rule makes recovered floating point portable.
* `Rotate` and `SetRotated` turn the opposite way to `RotateZ`. Zero-direction cases keep part of the old vector: `Project` keeps x, `Reject` clears only x. All original behaviour.
* `fcos` carries more bits than a double, which decides `1 - cos` at small angles: 1.4 million differences until `AtOneMinusCos` existed.

## Mistakes and fixes

* The default for an x86 MSVC build is SSE2, so recovered code ignored the x87 setting. I read mass differences at 24 bits as a bug before seeing that.
* My first constant for the shortest length, 1e-5, was a guess: the byte value is 5e-6. Caught by reading it.
* A test of mine expected a rotation the wrong way. The oracle-verified original was right.
