## What the formats are

From the code and the 20 real files, one of each per user interface archive (`DataXbox/UI/Xbox/*.JAM`):

```
.AFT    Text\name.AFT: NameSpace "s"  Text[ n ] { Text i { String "8 bytes"  Font2D "8 bytes"  TextFormat i  Variable "string" } ... }
        The words inside a Text in any order, each optional; any other word is reported (code 0x27) and reading goes on.
        Loaded with, in this order: Text\name.AFX (the formats, already recovered), Text\Font.AGF when the file system has it (2 of the 20 archives), Text\name.AFT, then Text\name.AIS (the strings).
.AFA    AScript\name.AFA: NameSpace "s"  [ActionScriptFileVersion r]  ScriptBlocks [ n ] { Script { ScriptID i  ScriptBlockSize i  Instructions[ k ] { len b1 .. blen  ... } } ... }
        Only NameSpace is checked. After it, the reader takes tokens by position: one more if the first is ActionScriptFileVersion, then the count is the third token's number, and so on.
        Each instruction is a length and that many bytes (each token's low byte), packed one after another into a block of ScriptBlockSize. The bytes are Flash action codes as 16-bit fields (150 = Push, 29 =
        SetVariable, 154 = GetURL2, 157 = If, 153 = Jump, 140 = GotoLabel, 0 = End, by the SWF numbering).
        The strings are AScript\name.AIS, loaded first, through AtIoContext::s_instance (0x002C62F0), not the file context.
```

## Is AScript an interpreter?

Yes. The scripts are Flash action bytecode, and AtFpActionScriptVM runs them: its handlers are the functions from 0x0001CB30 to about 0x0001EF70 (some 45 of them, 100 to 560 bytes each), with a stack of 30 values of 0x2C bytes.
Per the brief, what is recovered is the loader and the data structures: the scripts' storage, the machine's state, its stack and values (the value's four virtual slots included, since they are its storage's own code). **The
interpreter itself is not recovered.** Nothing that loads calls it, so no seam was needed for loading; anything that would run a script has no recovered entry yet.

## What the green result does not show

* **What stands in, the same on both sides**, each logged with its arguments: the strings' load (AtTextTable::Load 0x0001FA70, suite txt), the font database's load (0x0002A290, suite agn) and lookup (GmNameMap::Find
  0x00025150, suite gm), the graphics database loader and its texture count, and the owner, factory, font loader and fonts. So the .AIS and .AGF files are not read here; the formats (.AFX), sprites and shapes are, for real.
  The strings' stand-in marks its table loaded, so that the Clears are seen to clear it.
* **Real files reach only part of the format.** No real .AFA lacks the version; every real text has a String and a TextFormat. The no-version path, empty blocks, bad words, every heap and no-room path, ReleaseFont and the
  texts' Release rest on written text and direct calls. No real file reaches Release or ReleaseFont: only running a level would.
* **Crash cases, compared only up to the crash.** A failed request is reported and the code goes on, writing through the null it got: each request failing in turn ends in a fault on both sides, and only what comes before is
  compared. The same for a missing .AFT or .AFA, and for a value's Reserve that gets no room. What a crash leaves is not compared or freed.
* **Not run: an .AFA read one token out.** A file without the version but otherwise like the real ones reads every field one token late, and writes past its blocks until it faults, on both sides, taking the harness's
  heap with it. The no-version branch is run on text written so the count still lands on a number.
* The script's bytes are compared up to the last instruction's start plus 0x100; the size made room for is not kept, so its end is not known to the harness.

## Quirks of the original, kept

* The text table's Load takes a fourth argument, the level's "own fonts" (`m_fontSourceLevel == -1`), and never reads it: the fonts are always looked for, as `Text\Font.AGF`.
* `AtFlashText::Read` sets m_read after ReadData, which has just set it.
* ReleaseFont, given a demand-loaded font it cannot find among its references, counts down the first reference instead; at none, the font is unloaded. A count already at none wraps.
* The fonts' Clear reports a font still held and frees all the same, like the shapes' textures.
* The script reader checks only NameSpace and the optional version word; everything after is taken by position. Neither the instruction count nor ScriptBlockSize bounds what is written.
* The scripts' Clear frees the list only if the count is not 0, so a file of no scripts leaks its empty list; it does not clear the base table, and nothing uses the base's list or groups.
* AtFpScript::Free nulls only as many instruction pointers as were read.
* The stack's Allocate, when already allocated, frees first, which forgets the heap just given it; it then falls back on the stack's static heap, which the machine's Init has just set to the same thing.
* A value's Reserve compares sizes signed: a request of 0x80000000 or more makes no room. MoveTo overwrites what the destination held without freeing it.
* The text table's +0x2C and the script table's application before Load are never written by the constructors.
