# Images and fonts, the bodies of .AGI and .AGF: subsystem at/imgfont

Started 2026-11-08. State of this work: Semantic-tested. Nothing here is a byte match; a host MATCH from `tools/verify.py` is not a claim about the original compiler.

## What a real build does on real files

Nothing in a real build makes an image or font database: `AtDatabaseLoader`'s MakeImages and MakeFonts are pure, and so are the databases' MakeItems, MakeFonts2D, ImageAt and Font2DAt. Their concrete classes, and the concrete items they make, are in the graphics layer, which is not recovered. Given a concrete database and concrete items, as the host test and the oracle provide, loading a real .AGI or .AGF runs in recovered code all the way through: the database, then each item's body word by word, with the real image and 2D font classes. Next the database calls OnLoaded on each item not marked DemandLoad. That slot is pure in the base classes, as it is in the original, and only the concrete item of the graphics layer fills it (0x00124CD0 for an image, 0x00123850 for a font; the image's calls the base's pixel helpers and the device, presumably to load the picture and make a texture, not established further). So a real build reads every word of these files and then has nothing to make of them.

Out of budget and out of scope.

## Seam

One call from a base class goes into the graphics layer: PassName (slot 5 of an image, slot 13 of a 2D font) asks its argument's slot 16 for an object and passes the item's name to that object's slot 12. `AtGrDevice` and `AtGrNameSink` stand for those two classes by those two slots; every slot stops with `AtFatal` and a message. Nothing in loading calls it.

## Oracle

The agn oracle (`tests/oracle/oracle_agn.cpp`) now compares real bodies. Its harness items are gone. On the original side an item is made by the original's constructor (0x00057E30, 0x000FEA00) and given a table of the original's base slots, with harness doubles only where the concrete graphics item's slots would be; the recovered side uses the recovered classes with the same doubles. The read slot is wrapped on both sides to log what the database hands it, and then runs the real body. After each load every item's fields are compared: name to its terminator, flags, format, material index, the list and database pointers as "this side's", the colour rectangle, the transparent colour, the character table byte for byte, and the unknown words. On fonts read from real files the search by halves is compared for every code to 0x1FF. What loading does not reach is called directly on items made the same way: a read over a read item, Init and Allocate over read and made items, BuildCharacterSet with and without room, FindCharacter on sorted, unsorted and duplicated tables, SplitStrips over a grid, PassName, the colour setters, FreeData, and the complete and deleting destructors, the base font's included.

The imgfont suite (`tests/oracle/suites/imgfont.py`) runs this oracle with its own entries and mutants; the agn suite runs it unchanged.

## Quirks of the original, kept

* An image's MatAssignment is stored as 16 bits before the range test, so 65536 is index 0 and passes. A font's is 32 bits. Either way an index out of range is reported and kept.
* PntSource is in the image table but has no case: it is reported as a word that is not an image's.
* PlatformSource sets its flag and then the Dds source.
* An image's source words replace bits 9 to 11 only; a 2D font's source words assign the whole format, so a source after FrequentModify or InfrequentModify drops them.
* TransparentColor sets three bytes and leaves alpha; SetTransparentColor sets all four.
* ColorRectangleCharX and ColorRectangleCharY set flags and read nothing.
* A font's Read empties it only when it holds characters, and then through slot 8, which in the 2D font empties only the 2D font's fields: the base's flags, count and scales stay. Nothing marks a font read.
* A second CharacterSet is reported, and the first table leaks. A string in a CharacterSet gives one character for each byte, sign extended, and is not held to the count: one longer than what is left writes past the table. A token that is neither string nor integer is reported and the loop goes on, so text that ends inside the set never leaves it.
* FindCharacter starts at count / 2, not (count - 1) / 2. A code not found gives 0, the first character; a newline not found gives -1.
* AtGrI2DFont::FreeData frees the table and leaves the pointer, so a later Free frees it again.
* Free and the destructors leave the colour rectangle as it is.
* Text that ends inside an image's or font's body loops on the report for ever, as a light's does.
* Allocate with no characters sets the count to 0 and nothing else.

## Not compared

* The bytes of an item's name past its terminator: the database's buffer is copied whole, and past the terminator it is stack on both sides.
* A CharacterSet string longer than the room left: it writes past the table on both sides.
* AtGrI2DFont's +0x60 from new: the constructor does not set it. Both sides start from the same fill.
* The deleting destructors' delete branch on the recovered side is the derived test class's, compiler-made.

## Not recovered

* The concrete image (0x0028B9B8) and font (0x0028B970), whose slots the base classes leave pure: OnLoaded, the texture loaders, Slot0 to Slot3 of an image, Slot4, 11 and 12 of a font. The concrete databases (0x0028A794, 0x0028A774).
* AtGrI2DFont's slot 3, 0x000FF510, and the font strip builder 0x000FED10-0x0010015C with its comparator 0x000FE9C0.
* The image helpers 0x00057F50, 0x00058180, 0x000582F0, 0x00058710 and 0x00058A90, which only the concrete OnLoaded calls.
