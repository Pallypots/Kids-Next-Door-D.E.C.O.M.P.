# What a 2D texture does when it loads (subsystem `at/texload`)

Worktree branch, for the integrator. State: Semantic-tested. No byte match is claimed: the host compiler is not the original's. Names are inferred but for two phrases of the original's messages, "pixel map" (0x002774D8) and "DDS" (0x0028B034 and others). Started from the shader and font branch (`worktree-agent-a7b6aa05d8d4c4114`, commit 717fcc5).

## What a green result does not show, first

The device is the harness's on both sides: making a texture (0x0020B160), a level's surface (0x0020B220), describing a surface (0x0020AAB0), locking one (0x0020AAD0), the front and back buffers (0x00208430) and releasing (0x00205D10, 0x00205E20, 0x000FB630) are doubles that log their arguments and keep the bytes written into each locked level. So are the owner's format chooser (its slot 16) and its texture limits (+0x34), whose classes are not recovered: the oracle runs them identity and in four other modes, with several limits and capability words. A green result shows the original and the recovered code ask the device for the same textures (size, levels, format, usage), describe and lock the same levels and leave the same bytes in each, from every real .DDS file and every 2D texture of every real .AGT. It does not show what a real Xbox device makes of them, nor what the real chooser picks.

## Where the pixels come from

A .DDS file named for the texture (its eight letters, then `.Dds`), found on the I/O context's file systems with the .AGT's directory pushed. Not an .XPR: the disc has none. All 1,611 distinct .DDS files in the archives (4,134 entries) are ordinary DirectDraw surface files, header 0x7C, compressed DXT1 (629) or DXT3 (982); 56 carry several levels (3, 6 or 7). Of the 2D textures in .AGT files, 2,297 say DDSSource or PlatformSource, 58 TGASource, 4 BMPSource, 1 TplSource, 1 ProgSource. DXT data is copied as it is: no swizzle applies to a compressed format on the device, and no palette is involved. `analysis-local/scratch/texload/survey.py` counts them.

## Not recovered: what stops

* The device's calls, now in `src/at/AtGrD3DTextureSeam.cpp` beside the old ones: `AtGrD3DGetBackBuffer` 0x00208430, `AtGrD3DCreateTexture` 0x0020B160, `AtGrD3DSurfaceLevel` 0x0020B220, `AtGrD3DDescribe` 0x0020AAB0, `AtGrD3DLockRect` 0x0020AAD0. They are the Xbox Direct3D library's. `AtGrD3DLoadTexture2D` is gone: slot 12 is real code. The device's unlock is 0x001CC9F0, an empty function folded with many others; not a seam.
* The owner's format chooser and texture limits: declared as interfaces (`AtGrD3DFormatChooser`, `AtGrD3DTextureLimits`), their classes not recovered.
* Through `AtGrD3DUnrecovered`, each the first function of its branch: the readers for other sources (0x000FCE80, which with 0x00060430 chooses the BMP, TGA, TPL, PNT or TM2 reader; classes constructed at 0x00068B60, 0x00069790, 0x0011BD20) and their level loading (0x000FC790); a device format the file's rows cannot be copied into, staged and converted (0x000FDB70, 0x0011D180, and in Lock and Unlock 0x000FD870, 0x000FD5A0, 0x000FDC90, 0x0005F370); an owner keeping copies in memory (owner +0x30 bit 2: 0x000FD330, 0x000FD380, 0x000FD040); the palette for an indexed format (0x000F5D40); a level of another format or size, converted (0x0005F280 and on). No real .DDS reaches any but the first.
* Slot 11 of the 2D texture takes four arguments where `AtTextureItem::Slot11()` declares none: `Make` is its body and `OnLoaded` calls it directly; the virtual still stops (see Request).
* The material's slot 0, 0x0010B7F0: its closure is 159 functions (41,898 bytes, inflated by mid-function entries of an unrolled routine), far past the budget. Untouched; it stays the seam. `analysis-local/scratch/texload/closure.py` counts both (slot 12's, before this work: 132 functions with the Direct3D library and C library in them).

## Quirks of the original, kept

* `AtGrD3DFitSize` means to round each side up to a power of two, but shifts the same word again on each step: the bits it looks at are 0, 1, 3, 6, 10, 15, 21, 28, and the multiple is of 1 shifted by the step. 33 stays 33 and 9 becomes 12; a power of two comes back unchanged.
* `Prepare` sets the transparent colour and then sets the surface's flags to loaded alone, which forgets the colour key's flag.
* `LoadLevelsFromDds` keeps the last level's surface from one level to the next when there is no texture.
* A compressed level is copied in rows of blocks counted from the surface's height, not the file's; a file whose header claims more than it holds is copied past the device's rows.
* The DDS reader's destructor does not free the file's bytes; `Free` does.
* `AtGrIPixelMap::Fail` makes a text 0x18 longer than the message for the name, ": " and the message; the name is always empty.
* `AtGrD3DChooseFormat` constructs a pixel format on its frame and never uses it. Usage bit 0x80, which no .AGT word sets, makes a texture square.
* `OnLoaded` takes the front or back buffer and drops the device's reference at once, keeping the pointer; such a texture is not marked loaded.

## My mistakes

* Read the rounding loop in `FitSize` as a plain highest-bit search; the oracle's odd-sized Prog case showed the cumulative shift.
* Wrote the owner-copies branch as one stop where the original takes two ways; caught by a written case.
* Harness: a path key freed after logging resumed (a false 'D' on one side); fixed-size lock buffers that a short DDS file overran; and one owner kept across .AGT files after a stopped load left a freed database in its tables, which hung the next load.
