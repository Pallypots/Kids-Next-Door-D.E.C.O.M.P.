For the integrator: this holds what belongs in docs/formats.md, docs/verification.md, docs/STATE.md and docs/startup.md. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

**What a green result does not show, first.** The oracle runs the original's code for everything recovered here, but what is not recovered is a double on both sides: the base class's word parser 0x0015D000 (which in the oracle only skips a base word's block) and its Finished 0x0015D920, the sound notes' item (recovered on another branch), and every function an item loads into (behaviour lists, scripts, trigger and subscriber tables, VFX databases, dynamic nodes, the sound manager's banks, music chains). So it shows that the parser, its arrays, the queue, the items and their teardown agree with the original's; it says nothing about what any database does with a path.

## What the format is

A `.MNG` file is a level's load list. 51 distinct real files: `LOADER.MNG` under each `DESIGN\LOCATION\<level>\` (31), one to a playable character and look under `ART\CAST\PCS\...` (18), `PERSIST.MNG` in `Persist.JAM` and `UI\UI.MNG` in `MainMenu.JAM`. Each word names a kind of database and is followed by a counted list of paths:

```
// Level:    Lbkyrd1
SoundDatabaseLoaders[ 16 ]
{
   "Audio\Objects\bzappr\bzappr"
   ...
}
SceneDatabasesLoaders[ 60 ]
{
   "Art\Location\Lbkyrd\vistest" InSpaceGraph InsertInSnoopie
   "Art\Objects\Region\BoxReg" NotInSpaceGraph
   ...
}
VFXDatabases[ 22 ] { "Art\VFX\ItmspF\ItmspF.VFX" ... }
```

Two keyword tables, the original's words: the base's ten at 0x002B9350 and the level's sixteen at 0x002B9200 (ids 0x39 to 0x52). The level's Parse makes a tokenizer of its own, has the base install its words on it, and then installs its sixteen inheriting them.

Every word reads `[ n ] {`, allocates n items with new[] from the heap at 0x003B3610 (pushed around the allocation; null is reported with -2, no memory with -4), configures each from a request on the stack (`m_path` at +4, a context at +0x84 and +0x88), then reads `}`. After the parse, AfterParse queues the base's arrays and then the level's, in a fixed order, and the time-sliced loader runs them one at a time; Finished registers the sound nodes', the sound notes' and the instance sounds' data once all have run.

## Classes, and the class at 0x0015CD10

## What a real build does on real files

No recovered caller makes a `GmLevelManifest` yet: start-up (0x0008E660) is not recovered. Driven directly, as the host test does: a real build constructs one, opens a `.MNG` file through the recovered loader, and parses. 50 of the 51 real files begin with a base word (SoundDatabaseLoaders in the levels' and characters' files, GraphicsDatabasesLoaders in PERSIST.MNG), and a base word goes to `GmDatabaseManifest::OnToken`, which stops with "Level manifest: the database words (0x0015D000) are not recovered". ## Quirks kept

* A word given twice replaces its array without freeing the first.
* DynamicNodes does not read its closing brace: the brace reaches OnToken as a token of its own and goes to the base, which lets it by.
* The first seven words' paths are limited to 127 characters (reported, and copied anyway); the last five are not limited. A path of 128 characters overruns the request's buffer by its terminator, into the context at +0x84, so a later path of the same word gets an owner whose low byte is cleared.
* TriggerDatabases and SubscriberDatabases leave the request's context unset: their items do not read it.
* Free gives lists, scripts and effects back through the game's owners at 0x003B35D4 and 0x003B3C28, not through the owner each item was configured with.
* Free calls slot 0 of each GOO, GOC and GOI item before the array's destructors, which call it again on cleared items.
* `GmLevelManifest::Finished` registers every GOO item's bank, null ones too; GOI items register only what they hold.
* A GOO item with no bank free loads nothing, says nothing, and still counts as loaded; a GOM item run twice loses its first chain.
* `GmVfxItem`'s slot 0 forgets its database without deleting it; ANL, SDL and ASL items likewise forget their list.
* Every Run builds "%3s][%s" from the extension and path into a 0x200-byte buffer and never uses it; GOO, GOM and DAC build it twice.
* Videos, Streaming, Texture and Node are keywords of the level's table that nothing handles.
* `GmManifestLoader`'s path is 0x40 bytes, not 0x44: the base clears a field at +0x98.
