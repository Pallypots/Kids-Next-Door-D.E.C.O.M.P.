## What a real build now does on real files

`test_actor <file>` over all 652 distinct `.ASN` texts: **652 load and clear with nothing reported.** It was 430, with 222 stopping at "this class of node is not recovered". Those 222 are the files with a ParticleSystemActor.

Every class of node a real file uses is now real. That is not a game loading a level. On that scan the device, matrices, and all the device's and owner's tables are stand-ins. ## The table at 0x002AF0B0

**No code builds it.** It is initialised `.data`. Every reference in the XBE to the table's own range is a `movzx` read: 15 sites, in 0x0001E8D0, 0x0004C3B0 and 0x0004C8B0. I scanned every section for any 32-bit value in the table's range. The only other hit in `.text`, at 0x0008987A, is the bytes of a call instruction. The hits in other sections, D3DX, XACTENG, WMADEC, `.rdata` and `.data`, I took as chance bytes from their values and did not read one by one.

**But its contents do come from a formula, found by search.** All 2048 words are the Microsoft C library's `rand()` masked to 11 bits:

    state = state * 214013 + 2531011;  word = (state >> 16) & 0x7FF

The state that gives word 0 is 0x0332F1A2 in its low 27 bits. The top five bits never show, so 32 states fit equally, and the seed given to `srand`, and how many calls came first, cannot be told from the table. Search: every 2^32 start state against ten ways of taking a word; it found exactly those 32, each matching all 2048 words. The search stopped after this generator, the first in its list.

So `src/at/AtRandom.cpp` computes the table, and **no table is pasted into the repository**: only the state and the two constants, which are public. `oracle_particle` compares every word with the owner's XBE. For the integrator to decide: this is a formula that happens to reproduce data, not what the original's code does. In the original it is data. It is built lazily on the first word asked for.

**That inference is the weakest thing here.** 0x0005ACC0 reads drawer+4, then that's first word, then calls its slot 1. That this is the owner comes from pairing it with 0x0005B2E0, which calls slot 0 of the owner's first word's object, and passes the owner to the drawer's slot 1. No real slot 1 was read to confirm it stores the owner there.

## Oracle

Compared on all 652 files, for each particle system: every word of the actor, with the emitter by which one it is; the array's count word; each layer's words; the drawer's identity and owner; each particle's sixteen words; the cursor after each scene; the log and hash of calls to the maker and drawers (which emitter, which owner) and heap. `Emitter`, `WorldAdditiveInitialVelocity` and `WorldAdditiveAcceleration` are now compared on real files; 108 of the 652 have at least one of the words `WorldAdditive*`, `UpdateAtDraw`, `PlayParticles`, `PauseParticles`.

**The emitters are not real.** Each name in a file has a stand-in, the same on both sides, with 0 to 4 echoes, 1 to 7 particles, and colours and spheres from a hash of its name; a name space's is a different one. Real `.ASE` values were not used, so a real count or number no stand-in has is not tested. `.ASE` emitters at `MaxParticles` 0x80, the reader's default, are larger than any stand-in.

Cases in `oracle_particle`: all 652 files, each loaded twice, cleared twice, destroyed; written text for each word and error path, with three headers; 60 names by both tables, to go through the shapes; no heap and no memory for each of the two heaps; directly: the table word by word, layers over what is there, stale words, the cursor over its wrap, the lookup, clearing with layers, and reading over a loaded actor, which a scene never does.

### Limits and things not run

* After any crash only logs and messages are compared, as in the asn notes. No `Emitter` word, or none found, crashes on both sides, through the null, after the report. In the game the report would not return.
* The drawer's slot 0 is not called here on either side; the doubles' is empty.
* `kPlaying` and the state values 1 and 8 are compared, but what they mean to the update is not established.

## Quirks of the original worth keeping

* A `BoundingSphere` in a particle system's text is lost to the emitter's `LocalBoundingSphere`, wherever it comes in the text. Real files have one, for nothing.
* Its world sphere is simply a copy of that at loading: it does not go through the coordinate system there.
* The second name of `Emitter` is the name space. Real files give it empty.
* A missing emitter reports, and then reads through the null.
* The first layer has an all-zero colour, w too; a layer's constructor and Clear leave (0, 0, 0, 1).
* `Reset` leaves +0xF4 alone, so it stays heap fill until something sets it, even after the constructor.
* A layer's Start asks only its emitter word whether to Clear.
* `PlayParticles` sets the state and does not clear the flag `PauseParticles` set.
* Each particle system takes one draw from the random table when it loads, so the order of loading changes later draws. A fidelity concern if anything else depends on the sequence.

## Portability notes

* The array's count word is `AtSize` on the host, as in `AtSceneArray.h`; offsets are checked on x86 only, and the host test runs on x64.
* The sum for a colour is written with `double` for what the original keeps in an x87 register, one rounding to float after each term.
* `AtRandom.cpp` assumes `unsigned int` is 32 bits, for its wrap.
