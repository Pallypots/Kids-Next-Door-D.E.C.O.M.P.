# Worklog: bounding geometry, .ASB (2026-11-07)

For the integrator: this holds what belongs in docs/formats.md, docs/verification.md and docs/portability.md. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

## What the format is

Text, a sibling of `.ASN` in form but with a table and a reader of its own: named collision shapes. This comes from the reader at 0x00040AA0, the keyword table at 0x002B21A0 (14 words), the original's message "Node type must be jointed for bounding geometry", and the 239 distinct real files.

```
NameSpace "x"                  optional
BoxBoundingGeometry[n]         any order, each optional, counts only
SphereBoundingGeometry[n]
GroupBoundingGeometry[n]
BoundingGeometry[count]        the list proper. End of file before it is accepted: empty
{
    BoxBoundingGeometry "name"    or Sphere..., Group...
    {
        Parent "name"             earlier in the file
        RotTransCoordSys 1        a joint of the node's skeleton, from 1; none or 0 is the node's own coordinate system
        Box cx cy cz hx hy hz     half sizes; absolute values are taken
        BoxMinMax x y z x y z     or corners
        Sphere cx cy cz r         on a sphere; absolute radius
    }
}
```

ConeBoundingGeometry, CylinderBoundingGeometry, Cone and Cylinder are in the table, and nothing reads them: they are reported. No real file uses NameSpace, BoxMinMax, Cone or Cylinder. 172 of the 180 `RotTransCoordSys` in real files say 1; the highest is 4. Real files hold 271 boxes, 40 spheres and 240 groups, and the groups are the roots the rest hang from.

## What a real build does on real files

A real build **reads every real .ASB file to the end, with nothing stopped by a seam**. The format's whole closure of reading is recovered: `Load`, `Read`, the words, the classes' constructors, the owner's table. `AtSceneNode`'s `BoundingGeometry` word (0x000499B0) finds what this files.

What stops with a diagnostic, in `src/at/AtBoundingGeometryHost.cpp`, is at run time and not at load: a sphere's segment test (0x000434C0), the query's insert and finish (0x000552B0, 0x00057B50), and moving a normal into world space (0x000327B0). They are key `particle`'s to recover. So in a real build, today: overlap between any two shapes works given a context; a penetration test stops at the first normal; a sphere's segment test stops; a box's segment overlap works; a box's segment collection stops at its first hit.

And nothing calls any of the run-time half yet. How a running game enters it is at 0x00053B70-0x00054286 (setting the context, and walking two trees of geometry), which is on no list and not recovered, nor are the node's slots that call those. The context is public static members here; only the oracle and the test set them.

## Not recovered

* 0x00055520, the rest of `AtSegmentHitList`, and the class derived from it (vftable 0x002770F8, 0x00057AA0 and on). `AtSegmentQuery` here is only its array at +0x90.

## Oracle

`python -I tools/oracle_run.py --suite asb`. See the end of this file for the result on the final source.

What stands in for what, first: **the four functions of the seam are the original's own code on both sides**, called through a thin function, so they are exercised but not recovered by this. Nodes are the harness's, with the class at +0x08, the slot at 5 and the database at +0xA0, the only things this code reads of a node. Matrices are the harness's arithmetic, the same on both sides and logged. Coordinate systems are the recovered classes on both sides, already tested by suite asn.

Compared: every field of every geometry, pointers by what they lead to; name maps; the group a database is in; the arguments of every matrix call in order; every result to the bit, at double precision where the original returns st0; the context after each call; contacts and hits.

Cases: all 239 distinct files, each on two fills, each loaded twice, cleared twice, destroyed, and on one fill its first shapes tested in pairs through every slot. 73 written texts on two fills: each word, each error, each list twice, lists too long, cut short. 4,000 rounds of random boxes and spheres directly on the arithmetic, a third with infinities, NaN, zero and huge values; rotations of six kinds, so that axes along one another reach the parallel tests. Exact boundaries; the eight combinations of a sphere past three faces, each sign; every crossing of each face of a box by a grid of segments, to set all twelve bits (seen: 0xFFF). 64 rounds of 25 pairs through the slots, with joints or without, coordinate systems or without, contacts or without. Direct: drawing in ten shapes; the vertex format on 14 flags by 6 counts by 7 counts; the hit list in every state; the contact list; a jointless node, and one with no database.

### Limits and things not run

* A name that is not a string, in `NameSpace`, `Parent` or a geometry's name, leaves an uninitialised stack buffer in use on both sides. Not run. An early version ran one and differed, in the slot the garbage hashed to.
* Two boxes where no axis beats the starting depth, because of infinities or NaN: `Penetration` then never writes its normal, so slot 4 moves uninitialised stack into world space, on both sides. The depth is compared; the normal and that call's log are not. Only written and random awkward values reach this, and the harness counts them on its last line. It first showed as one difference, after a change of random seed; I checked the cause by reading the code and by the count, not by inspecting the stack.
* NaN are compared as NaN. Which of two NaN arithmetic leaves, and its sign, is x87 against SSE: logs of inputs and results canonicalise them.
* The array form of the hit list's deleting destructor has no recovered twin; it is compared with the compiler's `delete[]` by its calls to the heap.
* `<` against `<=` in the edge tests is compared only where equal values can be built. Those mutants would be equivalent on the cases here, and are mutated to the opposite instead.
* Parallel axes to within 5e-6 are reached by exact rotations about one axis, not at the edge of that tolerance on both sides of it, except where random rotations happen to.

## Quirks of the original worth keeping

* **`Clip` has a real bug.** On Z, a backward segment leaving through the low face interpolates from the end to the start, where every other case goes from start to end: `clippedEnd->Lerp(*end, *start, t)`. So the clipped end is wrong, and only there. Kept as `swappedEnd`.
* `SwapNodes` swaps the two nodes in the context and not their two coordinate systems, though a box against a sphere asks the box with the two swapped: the coordinate systems stay the wrong way round for it unless both are joints.
* `DrawSphere` takes the sine of the angle as it stood in the register and the cosine of it after a store to float. They are not quite one angle.
* The only result returned unrounded from `AtBoundingBox::Penetration` is the last edge's; every other is the stored float. A sphere's `PenetrationAlong` returns unrounded too. Hence `double` in those signatures.
* `OverlapsSphere` and `PenetrationSphere` never read the box's centre: the caller has already taken it off.
* `UpdateDrawing` on a coordinate system with no parent, up to date and asked with `multiply` 0, copies anyway. With a parent it returns.
* A second `Parent` for one geometry is added to the second's list and stays in the first's.
* A list given twice is reported, and allocated again, leaking the first. Too many of a kind in the list is reported, and then the array is overrun.
* The database's arrays have no count ahead of them and no destructors are run: their classes have none.
* The hit list's `Reset` leaves `m_current`, and its constructor therefore leaves it unset.
* A sphere's `PenetrationAlong` normalises its direction twice.

## Requests and shared edits

Additive only: `AtCoordSys::UpdateDrawing` and `TransformDirectionInverse` in `include/at/AtCoordSys.h`; `AtNameTableOwner::AddGeometry` in `include/at/AtNameTableOwner.h`. All defined in `src/at/AtBoundingGeometry.cpp`. No shared member is renamed or retyped. No suite that uses them was touched.

For the integrator:

* **`AtVector3::DistanceSquared` and `NormalizeReturningLength` are declared `float`, and the original's leave an unrounded value in st0** (0x00042DC0, 0x00042EF0). They cannot be used where the caller goes on with st0. `src/at/AtBoundingMath.h` has `DistanceSquaredHeld` and `NormalizeHeld` for this. Changing the two to `double` would be better, and touches their other callers; I did not.
* `g_atGeometryMatrix` holds three of the matrix table (0x002C61F8, 0x002C61FC, 0x002C625C), kept apart so as not to disturb `AtMatrixTable` while others add to it. They belong there. Key `particle` needs 0x002C625C for 0x000327B0 too, and may have added it.
* Seams to delete when `particle` lands: all four in `AtBoundingGeometryHost.cpp`. `particle` also owns 0x000552B0 and 0x00057B50, which are methods of the class named `AtSegmentHitList` here (and `AtSegmentQuery` for its derived part): **its branch may name that class too**. Likewise 0x000434C0 is a method of `AtSceneSphere`, and 0x000327B0 of `AtCoordSys`.
* `AtBoundingBox` shares 0x000320A0 with `AtSceneAnimBlend`'s constructor by folding, as `[symbols]` says.

## Portability notes

* Arrays are `sizeof`-based, so 0x38, 0x30 and 0x20 bytes on the Xbox and larger on x64; nothing depends on it.
* A joint is reached through `AtSceneJointedModelActor::m_joints`, by a cast from a node whose class the code has checked or trusts.
* `AtSegmentHitList` holds the 8-byte keys and 0x2C-byte hits opaque here, at those sizes on any pointer size. Whoever recovers what is in a hit should check that.
* `DrawBox`'s and `DrawSphere`'s `instances` is the address of the caller's own argument: one pointer on x64 too.

## Mistakes along the way

* I gave the seam for 0x000434C0 a `float*` where the original takes a vector, from reading how many stack bytes its caller set aside rather than the callee. It wrote past the variable, and the keys differed. Fixed from the callee's disassembly: a5 is the point of entry, and the seventh argument is what comes back when the start is inside the sphere.
* A word enum in an anonymous namespace had `kBox` and `kSphere`, and inside member functions the class's `kBox` = 0 and `kSphere` = 1 won, so the shape words were reported as errors. The oracle's first text showed it; so did the host test, by hanging.
* I wrote `!(dx > 0)` for "dx is zero or less" throughout the sphere tests. In the original, a NaN goes the other way. Caught on rereading the flags before anything ran, and held by mutants.
* The first oracle ran a text with a geometry's name cut off at the end of the file, which is the uninitialised name above.
* The first `test_asb` asked for exact equality after an interpolation that rounds.
* The first mutant run was 739 of 758. Real gaps, each now closed by a case: the query's flag 0x10 never set; a segment's near-parallel axes never reached with shapes apart; spheres exactly touching, where only the unrounded square differs; a node's own generation behind while its parent's was not; a base's kind, overwritten before anything looked; a joint drawn on a node not jointed; a hit list given storage while it owned some; both raises of a hit list; a format set twice. Mine: `texCoords > 7` still clamps 8 to 8, so that mutant changed nothing. Dropped as equivalent, with reasons in the suite: 3.
