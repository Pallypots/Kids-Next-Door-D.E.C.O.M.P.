# The graphics layer's object short of the hardware (subsystem `at/grlayer`), 2026-11-19

For the integrator: this holds what belongs in docs/startup.md, docs/STATE.md and docs/verification.md. Reference build knd-xbox-usa-5454008a-v1. State of
everything here: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler (blocked, docs/toolchain.md).

The brief named the subsystem `atlayers2`; `at/atlayers` is a prefix of that, so it is `at/grlayer` (suite `grlayer`).

**What a green result does not show, first.** The hardware is a double on both sides of the oracle: the factory's start (0x000C7C60) and stop
(0x000C7C90) are redirected to logging doubles, and the factory they hand back is one shared object with a table of doubles. So the oracle shows that
Init calls the start with the same saved globals and config, takes the same slots of what it gets back and stores the results in the same places;
it says nothing about the factory, the render function tables 0x000EC670 writes, or the graphics device. The matrix table (0x002C60C8, 0x1A0 bytes)
is compared only in the fifteen members the recovered code knows (include/at/AtCoordSys.h); the other 89 words are not compared. A real build stops at
the start, so nothing past it has run on the host.

## Quirks of the original, kept

* Init writes 2 back into App's config when its kind is 1.
* Restore copies each function table from where Save noted it, which is the live table itself: for the render table that copies its matrix part over
  the matrix table. Before the factory's start fills both, the render table is zero, so the start's own Restore empties the matrix table (on the host
  the start is a seam, so this is not reached).
* The derived half of the heaps sets AtMatAssignment's, AtShader's and AtImageDatabase's heaps twice; the base and the derived half overlap in fourteen
  more; config +0x30 goes to two setters (0x00100DB0 and the factory's 0x000EB510), +0x34 to two, +0x5C to AtMaterialDatabase and 0x000F7780, +0x70 to two.
* The name map's and namespace database's heaps are set only if not set already, in both halves.
* The layer's constructor clears +0x24 again after its base did; neither constructor writes +0x30 or +0x4C.
* The base's slot 6, a frame, always returns 1 (folded with AtBoundingGeometry's TestSegment): the graphics layer never ends the main loop itself.
