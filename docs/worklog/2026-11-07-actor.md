# Worklog: the actors of a scene (2026-11-07)

For the integrator: this holds what belongs in docs/formats.md, docs/verification.md and docs/portability.md. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler.

## What a real build now does on real files

`test_actor <file>` is a real x64 build: the recovered tokenizer, scene and node classes, `src/at/AtSceneActorsHost.cpp` and `platform/fatal.cpp`. No class of node is a stand-in. What does not exist yet is: the device and its matrices, and what the device's tables hold, which comes from other files. It stands in one entry for each name in the file.

Over all 652 distinct `.ASN` texts: **430 load and clear with nothing reported. 222 stop with "Atlas Scene: this class of node is not recovered".** Those 222 are exactly the files with a ParticleSystemActor. Before this work, the files that load were the 15 with only Node and ModifierNode.

This is not a game loading a level. The meshes, animations and databases are not really there, and nothing is updated or drawn.

## Oracle

`oracle_actor` shares `oracle_asn.cpp`'s harness, by including it. **ModelActor and JointedModelActor now run for real on both sides in both suites.** Compared on all 652 files, for each actor: every word of it; every word of each animation channel and material channel; each blend's counts and contents; the set's fields; each copied database's map, fields, array counts, and every word of each coordinate system. Pointers go by what they lead to. Then the databases a jointed actor attaches itself to, and the log and hash of calls to the device, matrices, heap and file, as before.

The classes still doubles are now the real actor base under a reader that takes three words. So on real files what is consumed and not compared is only, on a ParticleSystemActor, `Emitter`, `WorldAdditiveInitialVelocity` and `WorldAdditiveAcceleration`, and its own `Mesh` if it had one. Its base's words are compared. The particle class's own fields past +0x98 are heap fill on both sides, and nothing writes them.

Stand-ins on both sides, the same: the device's tables. A name beginning X is absent, Y is in a first table and not the second, Z is an animation with no frames and no rate. Each database has a shape that follows from its name's hash: some empty, parents of both kinds, some with a +0x10 matrix, some named elements. These shapes are mine. **Real databases from .AKC files were not used**, so a shape no stand-in has is not tested.

Cases in `oracle_actor`: all 652 files, each loaded twice, cleared twice, destroyed; written text for every word and error path on both classes, with and without a coordinate system; channels, in both lists; twelve orders of scale with the sphere before and after; shortages of each of the three heaps and the database's; directly, the cast, heaps, the deleter, sharing, a scale it owns, kind 2.

### Limits and things not run

* `AtSceneAnimation::m_rate`, `m_frames` and the same on `AtSceneMatAnimation` are the only fields of those classes known. They are views onto classes loaded elsewhere.
* A channel's listener (+0x0C) is never set in this path on either side, so the call to it is not reached in any case. Its mutants are therefore not listed.
* The destructor of `AtSceneMatChannel` at +0x00 to +0x10 and the like are compared only through what is freed, since the memory goes straight back.
* `AtSceneAnimBlend`'s elements have the original's empty constructor 0x00057E20 passed around, with nothing to see.
* The original's array destructors are run; they have no recovered twin to call. As in the asn notes.
* After any crash only logs and messages are compared, as in the asn notes. Errors whose report would not return in the game often crash on both sides here: a word naming what is not found, for example, with `CopyCoordSysDatabase "XGone"`.

## Quirks of the original worth keeping

* `PhysicsActor`, `PhysicsActorInstance` and, on a plain model, `PhysicsEntitiesFile` copy their string onto the current heap and lose it: a leak on each word.
* `InitWithHavokPosition` and `InitWithHavokOrientation` do nothing, on a model.
* `Rewind` sets the flags to 1, whatever they were. So starting a channel leaves exactly 7.
* The word given a start frame in PlayAnimation takes it modulo the frames, unsigned: `-5` is a large number first.
* A PlaybackRate before PlayAnimation still wins, since it is applied at the end. `m_speed` is rate over the animation's own, and only then.
* A set's blend is made only with more than one channel.
* `AtSceneAnimSet::Clear` frees channels with no destructors, and has none to call.
* A shared `CoordSysDatabase` attaches its root to each actor that names it, so the last wins, and each earlier one loses it.
* `ShareCoordSysDatabase` sets the coordinate system and scale to null without giving them back; they are from the scene's arrays.
* The same bit 0x800 is drawing on an actor and modification on a modifier node.

## Portability notes

* Channel arrays are `sizeof`, and offsets are checked on x86 only; the host test runs on x64.
* The stand-in views `AtSceneAnimation` and `AtSceneMatAnimation` have floats and integers only, so they hold on x64 as declared; real loaders must fill them.

## Mistakes along the way

* First test world shared one database among all names, and gave two real files a stack overflow from a cycle of coordinate systems. That was my stand-in, not the code; each name now has its own.
* A `std::string` in the harness's DataLink double allocated, on one side only, with logging on. It showed as a difference on the one long path. Fixed by hashing by hand.
* The clean-file counter first counted the opening message as a report, and said 0 files.
* My stand-in databases gave out more +0x10 matrices than their extras allowed, so copies ran into the pool's spare matrix. Limited now.
* I first wrote `m_root` for +0x2C, which would have broken the asn suite's mutant texts. Back to its old name.
* The first mutant run was 305 / 342. Six were provably equivalent, dropped with the reasons at the head of `tests/oracle/suites/actor.py`. The rest were gaps, now closed: mostly fields a load overwrites, or memory freed before it could be compared, now driven directly in `run_actor_fields`; and shortages where an earlier failure on the same heap hid the later one.
* **One of those gaps was in the harness from the asn work, and would have hidden real faults.** `canon_known` treated null as "unknown", so null and a pointer to nowhere known compared equal. Null is now known. The asn suite stays green with that stricter comparison.
* Making the doubles real moved two asn mutants to survivors, 411 / 413: `FinishBody: own coordinate system`, which no real class can now show, and `Joint: not moved`, which needed a real joint to attach to. A spy node and written text close them, and the mutants stay.
* Real file LETTERS.ASN has names X, Y and Z, which my rule for awkward names made absent. Reports on both sides were the same, so nothing showed but the clean-file count, 429. Only longer names are awkward now.
