# A sound emitter's voices, the voice classes and the Xbox bank's play slots (subsystem `at/emitplay`), 2026-11-19

For the integrator: this holds what belongs in docs/formats.md, docs/verification.md and docs/STATE.md. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler. Started from the sound playback branch (cfde019).

## What a real build now does when a note is played

Read this first. The emitter's play slots were the stop: `AtAudioEmitter::Play` and the rest stopped with "this slot of an emitter is not recovered". Now everything from the emitter to XACT is recovered, and the first thing a play reaches that is not recovered is an XACT entry point, named in the stop's message:

* A note whose segment's bank is loaded: `Play` (slot 15) makes a voice from the sound owner's factory, links it on the emitter, tells the system the emitter has voices, and asks the bank to prepare it. The bank's `Prepare` calls **`AtSoXboxXactPrepareCue`, XACTENG 0x00242189**, which stops: "Atlas Sound: no XACT on this platform: prepare a cue (XACTENG 0x00242189)". Supplied (as the oracle and host test do), it goes on to place the emitter's stream (**0x00242291**) and play the cue (**0x002421BC**).
* A note whose bank is not loaded: a voice is made, nothing prepares it, so it is never started; with no caller wanting it back it is released and goes straight back to the factory. No XACT call, no sound, no stop.
* Pausing, resuming and stopping reach **0x00242259** and **0x002421EF**; a playing voice's parameters reach **0x00242121**; a segment's length and distance (what `GmAudioData::PlayNode` uses for range) reach **0x00242226**; a 3D emitter's update reaches **0x00242291**; the Xbox emitter's `StopAll` reaches 0x002422BF, already a seam.

Two things stand before that in the game's own flow and are not recovered, so a real build still does not get there by itself: the sound owner's construction (what fills its factory with voices, and makes the system: 0x000E9E90 and the constructors of vftables 0x00288A30 and 0x0028A338), and, as before, the `.AOD` load, which stops at the first bank without `DelayLoad` (below). Called directly with an owner set up as the oracle sets it up, the play path above is what runs.

The closure, `analysis-local/scratch/emitplay/closure.py` in this worktree (run from the worktree): from the 52 functions and every slot of the emitter's two vftables, the voice's two, the system's first four and the Xbox bank's 3 to 9, 11 and 12, following direct calls, with 0x00011070, 0x000141C0, 0x00014230 counted as done. Result: 111 reached, **0 not recovered**; XACT entry points 0x00241DB6, 0x00242121, 0x00242189, 0x002421BC, 0x002421EF, 0x00242226, 0x00242259, 0x0024228C, 0x00242291, 0x002422BA, 0x002422BF, 0x002422C4; the C library 0x0012526B (the array destructor iterator), 0x00125559 (sprintf), 0x001256A3, 0x00125F25 (purecall).

## The `.AOD` loader's stop, looked at and not recovered

`AtSoXboxXactBank::Load` 0x0011F4B0 (561 bytes, the original's `vInitPlatformSpecific`) is not small and does not reach XACT itself: it names `<name>.WBA` (only for format 3), opens it through the bank's file (0x00024AA0, 184 bytes), takes a 0x224-byte block from the bank heap, starts an asynchronous read of the header into it (0x00024950), and then calls slot 10, `eUpdateLoad` 0x0011F6F0. With a header already read it instead sizes the file (0x0011F2F0), allocates through the system's slot 13 or 0x000EA850 and reads it whole. `Process` 0x0011F2A0 polls the read and calls slot 10 until step 8. **Slot 10 is where XACT starts**: a state machine of 2181 bytes and 42 calls, checking the XACT sound bank's version ("Incorrect binary version of XACT sound bank"), naming "%s.wba", reading more blocks, and calling XACTENG 0x00241DF5, 0x00241E38, 0x00241E7B and 0x00242011, with streaming wave banks as well. Recovering `Load` and `Process` (some eight functions with their file helpers) would move the stop from 0x0011F4B0 to 0x0011F6F0, which is still game code, not an XACT call; slot 10 alone is past this budget. So the seam stays where it was: `AtSoXboxXactBankLoad` in `src/at/AtSoXboxHost.cpp`.

## What the code is

* A voice is a play state (the original's word) and on the Xbox an XACT cue: segment +0x04, emitter +0x08, flags +0x0C (1 initialised, 2 released, 4 paused), state +0x10, the emitter's list or the factory's free list +0x14/+0x18; then queued voice +0x24, play flags +0x34, which of the bank's XACT sound banks +0x38, cue index +0x3C (the segment's index), the cue +0x40, and four parameters of 0x1C bytes from +0x48 (value, ramp time left, rate, flags, an eight-byte name). 0xB8 bytes. States, inferred: 0 preparing, 1 prepared, 2 queued, 3 starting, 4 playing, 5 stopping, 6 done. Nothing recovered sets 4: the system's update would.
* The factory is the sound owner's +0x04 (`AtNameTableOwner::m_device`, a scene device on the scene owner). Allocation takes the last free voice; out of voices reports "AtSoIFactory::poAllocatePlayState() : Out of playstates!" and gives null, and every caller copes with null.
* The system (the owner's loader, vftable 0x0028A338) keeps the emitters that have voices (+0x0C/+0x10, through the emitter's +0x48/+0x4C) and the banks (+0x14/+0x18, through the Xbox bank's +0x8C/+0x90). Its +0x5A0, called `m_directSound`, is the XACT engine: the stream's creation (0x00241DB6) and the variables (0x00242121) both take it. The stream functions that `src/at/AtSoXboxHost.cpp` calls `AtSoXbox*Stream` are in XACTENG too, so the stream is very likely an XACT sound source; their names are not changed here.
* The bank's slot 9 sends a playing voice's changed parameters as XACT variables, named by the parameter's name or, with none, by its index ("%d"); then starts the voice queued behind it if that one is prepared.
* `SegmentLength` is the cue's +0x34 milliseconds times 0.001f (so 1500 gives 1.50000012), or the largest float if the cue loops; slot 12 is a distance at +0x54, or the largest float.

## Quirks kept

* `Update` reads the next voice from each voice after updating it, and a voice let go is back in the factory with no next: the update stops after the first voice it lets go.
* `Start` on the emitter reads the voice's segment's bank before testing the state, so a voice with no segment crashes whatever its state; `PauseVoice` and `ResumeVoice` never test the segment; `StopVoice` tests both. `PlayAfter` reads the segment's bank before making the voice and never tests it for null; with no voice to play after it does nothing at all, not even hand back null.
* The bank's `Start` on a voice still preparing only marks it starting; it is played only from prepared (with play flag 4) or from any other state but preparing (without).
* The bank's `Queue` ignores `this` and prepares through the voice's own segment's bank. The bank's update starts the queued voice through the emitter and then overwrites the state its start gave with "queued".
* Stopping a queued voice with a cue only marks it stopping; without one it is finished. Stopping a starting voice only marks it.
* The bank's update writes the variable names eight bytes apart with a nine-byte copy: with all four parameters changed and the fourth named, its terminator lands on the first variable's type, which XACT then gets as 0 (12 such calls in the oracle).
* A parameter set over exactly 5 microseconds (4.99999987e-6) or NaN seconds ramps; under it, it is set at once. A step with NaN time left clears to "changed if just set".
* `SegmentLength` reads the milliseconds as unsigned: a negative value is a long time, not none; only -1 is none.

## My mistakes

* My first `AtAudioEmitter::Start` read the bank into a local before the state test, as the original does, but the compiler moved the read after it, so a voice with no segment crashed only on the original's side. The oracle found it; the bank is now tested first, which keeps the read first.
* A first host-test expectation took 1500 milliseconds to be 1.5 seconds; 0.001f is not a thousandth, and the original gives 1.50000012. The code was right.
* My first oracle drew random values inside the lambda that sets both worlds, so each world got a different value; caught on reading before any run counted.
* Two host-test expectations of mine misread the code (that a stopped queued voice with a cue calls XACT; that a second Release goes through an update); the test was rewritten to what the code does, which the oracle had already shown the original does.
* Four mutants survived the first run: gaps in my cases, listed above.
