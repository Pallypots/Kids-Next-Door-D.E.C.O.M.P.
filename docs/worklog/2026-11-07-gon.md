# Sound notes: `.GON` (subsystem `gm/gon`), 2026-11-07

For the integrator: this holds what belongs in docs/formats.md, docs/verification.md and docs/STATE.md. State of this work: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler; none of the 19 functions is a host match, and the one vftable is.

## What the format is

Not a game object file. A `.GON` file is the table that says which sound an animation's trigger plays: "sound notes". Established from the reader 0x00139090, its keyword table at 0x002B9090 (12 words), and the 49 distinct real files, all under `AUDIO\` (`AUDIO\CAST\ENEMIES\*`, `AUDIO\CAST\PCS\*`, `AUDIO\LOCATION\*`, `AUDIO\SFX\*`, `AUDIO\OBJECTS\*`), one to a character, location or family of effects.

```
NameSpace "x"                optional; the bank's name, which a search can filter on
SoundNotes[n]
{
    Note "name"
    {
        AnimationTrigger "t"     the name an animation fires; the note is found by it
        VFXTrigger "v"           entered in a third map, which nothing recovered reads
        GameEvent "e" "arg"      the second string optional; used by 0x00160030 through 0x001511E0
        ActorEmitter             the default: does nothing
        GlobalEmitter "sfx"      an emitter by name, from the sound owner's table (EMITTERS.AOE)
        Conditional "voice"      an emitter: 0x001386D0 plays nothing while it has a voice playing
        Stop "other"             0x001386D0 first stops the first segment of that note
        Singleton                0x001386D0 skips the play if the segment already plays on the emitter
        Segments[n] { "seg" 0.25 "seg2" ... }   names in the .AOS lists, each with an optional real weight, default 1; the load scales them to sum to 1
    }
}
```

Real files: 517 notes, 517 AnimationTrigger, 513 Segments blocks, 510 ActorEmitter, 7 GlobalEmitter, 4 Conditional, 4 Stop, 14 Singleton; no NameSpace, VFXTrigger or GameEvent, and no weights. Words are case-insensitive. Anything else inside a note, word or token, goes by without a report.

What the notes are for, from their callers (not recovered): `GmAcAnimationCallback` (RTTI name, vftable 0x0027C1D8) slot 4, 0x00160030, takes an animation trigger, finds the note by `FindNoteByTrigger` (first in the actor's own bank name, then any) and plays it with 0x001386D0; 0x00166FC0 does the same from a table of event handlers; 0x0017E760 finds notes by name for another class.

## What a real build does on real files

The item is what the level manifest's parser 0x00142E90 makes for each file under its GON word, and that parser is not recovered, nor is the concrete manifest loader whose `Finished` (0x00143CE0) calls `RegisterNotes`. So nothing in a real build's flow reaches this code yet. Called directly, as the host test does, a real build loads a real `.GON` file completely, registers it against whatever sound lists the manager holds, and finds its notes by name and by trigger. Nothing is played: 0x001386D0 is not recovered.

## Oracle

`tests/oracle/oracle_gon.cpp`, suite `gon`. Every real `.GON` file loaded through the file code on both sides, then registered against real maps of fake segments, then every quoted string looked up as a note, as a trigger (with bank filters "", "Space", "other") and as a segment, then freed and freed again; the bank destructors compared. Written text for each word and each report; banks allocated and released directly; three files in three banks of one manager for which bank wins and what the filter does; the item through its whole life, the two forms of its deleting destructor and the array form with flags 2 and 3.

Result: `NO DIFFERENCE OBSERVED: 49 files, 583 notes, 543 choices (19 with a scaled weight), 451 segments found, 105 absent, 11 emitters, 6 conditionals, 6 stops, 21 singletons, 4 VFX triggers, 6 events, 1100 lookups found, 36 stops at a crash; 49105 comparisons, 0 differences (0 in written cases)`; entries reached 19 / 19; mutants detected 131 / 131. The first run had 3 survivors: two were harness gaps (freeing a bank with maps but no notes; a segment name with no lists at all), now closed by cases. The third, dividing instead of multiplying by the reciprocal, is dropped as not distinguishable, with the reason in the suite. `--suite all --no-mutants`: all 34 suites show no difference. Host tests: 29 / 29 pass on x64.

Fatal reports stop that side, as in the game (AtFatal does not return): the host's AtFatal, AtPushHeap and AtPopHeap are patched in the harness so that both sides stop and count alike. Allocation failure is reached by failing the nth push of the audio heap.

Doubles stand for the sound lists (AtAudioDatabase with real AtAudioSegmentDatabase maps holding fake segment pointers), the emitters (a real GmNameMapGroup and map of fake pointers, at the sound owner's +0x90) and the file system. A green result does not show that the lists real `.AOD` files make give the same answers; their own suite covers them.

Not compared: a note's text ending inside its braces spins in the original (only a right curly ends the loop; Next returns 0 forever at the end of the data) and in the recovered code alike, so no written case does that. The bank name's bytes after the terminator, when there is no NameSpace: both copy eight bytes from an empty literal, and what follows each literal is its own image's; only up to the terminator is compared, which is all that AtNamesEqual reads.

## Quirks kept

* With no notes (`SoundNotes[0]`) the bank stays unused: m_notes null, the name not set.
* A Segments block with a count of 0 allocates 0 bytes, and FreeNotes never frees it.
* A second Segments block in a note leaks the first.
* Weights summing to 0 or less are divided by 1, so negatives stay negative; the sum is kept in a register (double), the products stored as float.
* `FindNote` and `FindNoteByTrigger` read `bankName[0]` before anything else in a bank in use; 0x00160237 passes null, which crashes once any bank is in use.
* `RegisterNotes` run twice enters every note twice, reporting duplicates.
* The item's `Run` builds "%3s][%s" twice into a buffer and never uses it.
* A file that will not open is reported and, if the report came back, the reader crashes on a null tokenizer.
