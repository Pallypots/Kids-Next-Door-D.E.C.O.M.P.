## Mistakes and fixes

* Modelled `AtIoTokenFile` as deriving from the stream. Its constructor leaves the stream's vftable and it has none of its own, so the stream is a member.
* Assumed `strncpy` for the message's extension and so an uninitialised read. The address is `strncat`, which terminates: no such quirk.
* Expected real values in the native test were the correctly rounded floats. The original's parser gives others. Now taken from the original and asserted against it.
* `%f` differs: the original's C library rounds ties up from 17 digits and drops the sign of negative zero. Found by the write test. Now reproduced, and tested on 300,000 floats.
* The original's `%f` needs C library start-up the harness does not run; it stopped with no message. The harness now calls the initialiser at 0x00125BC7.
* Harness bugs: a string growing inside a logged call counted as an allocation; a delete logged on one side only; a digest pass's calls left in the log.
* First mutant run 159/172: see docs/verification.md.
* Patch scripts via shell heredocs turned `\n` into real newlines again. Writing them with the file tool works. One script appended to the end of tools/jam.py after a failed match on CRLF lines; caught by the next run and repaired.
* A shell command read stdin forever: a stray `cat >`. Stopped it.
