# Sound bank and segment lists: `.AOB`, `.AOS` (subsystem `at/aob`)

State: Semantic-tested. No byte match is claimed: the host compiler is not the original's. Names are inferred.

## What the formats are

Established from the code and the text:

* An `.AOD` file lists them, under the words `BankDatabase` and `SegmentDatabase`. Files are under `AUDIO\` on the disc: 271 of each, 160 distinct contents of each.
* `.AOB` is a list of banks. `Bank[n] { Bank "name" { ... } ... }`. Each entry gives a residence (`DiskResident`, `SoundRamResident`, `PrimaryRamResident`), a format (`MsaFormat`, `MiaFormat`, `RwfFormat`, `WbaFormat`, `SbaFormat`, `GmdFormat`, `GmsFormat`, `PlatformSource`), `BlockID n`, `DelayLoad`, `Streaming`. All real files have only `PlatformSource`, with `Streamed`, `StreamedStereo` or `StreamedMemory` after it in 78 of 161 uses; the other words are reached only by written text.
* `.AOS` is a list of segments. `Segment[n] { Segment "name" { Bank "bank" "namespace" index  Looping } ... }`. A segment is a name for an index in a bank.

Not established: what a bank's data file is, what the format values mean to the player, and what `BlockID` selects. Those are in the concrete classes (0x0010EC80 makes a bank only for format 3, residence 0).

0x00025B80, 0x00025BB0, 0x00025BC0 and vftable 0x00273004 are `AtIoFile`, already recovered. 0x00025BE0 and 0x00025BF0 use the pool at 0x002C633C and are not part of these classes. The image draw lists at 0x0003B0C0 and 0x0003B490 also call 0x00031A30 and 0x00031A60, so that class is not only for sound.

## Quirks kept

* Both readers stop after the first `Bank` or `Segment` block: what follows is never read.
* Reading again after a count of zero crashes. A count of zero leaves a table, `Init` then clears through the virtual slot what was just set, and the owner is null. Both sides crash in the same place. The disc has no such file.
* An unterminated entry goes round for ever if the report returns, in the bank and segment loops, on both sides. In the game the report does not return.
* `ComboResident` is in the word table and refused by the reader. `Streamed`, `StreamedStereo` and `StreamedMemory` are taken and ignored.
* `GmdFormat` comes before `GmsFormat` in the table, with ids 0x48 then 0x47.
* A bank already in the owner's plain group is shared, even within one file, and the second description is dropped without any check. A bank in a name space is not looked for there, so a second of that name is made.
* The add methods treat only null as no name space: `NameSpace ""` makes a space with an empty name. The inline find in the segment reader treats empty as none too.
* A segment's fourth argument is unused. A later `Bank` replaces an earlier one, even when it is not found. Not finding a bank reports nothing.
* `AddUser` on a full table of 20 does nothing and reports nothing.
* Bank `Load` and `Unload` dereference null with no users.
* `~AtAudioBankDatabase` does not let go of its banks.
* `GetCurrentPath` failing leaves the directory buffer uninitialised, and it is passed on.

## Oracle

`python -I tools/oracle_run.py --suite aob --jobs 2`:

```
NO DIFFERENCE OBSERVED: 160 .AOB and 160 .AOS files, 160 banks, 1517 segments; 152766 comparisons, 0 differences
entries reached in every run: 40 / 40
harness mutation (--mutate): exit 1
(unmodified copy: positive control) passes
mutants detected: 244 / 244
```

224 as a difference, 20 by a crash or hang. Every real file is loaded through the file code with its partner, so all 1,517 segment references resolve to a real bank (checked separately from the text in Python, not counted by the oracle). Then a second list over the same banks, a read over itself, and each let go of. Also: 51 written bank texts and 37 written segment texts, each segment text three ways (banks, none, banks in a space); text left open, on a tokenizer that stops it after 40 errors; each method alone; directories with and without a root; no heap, no memory, no file.

The first mutant run was 241/247. Three survivors were real gaps, now closed:

* `Clear` with a count and no list was never run.
* A list's entries being cleared can only be seen from a bank's `Reset` during the clear, and nothing looked. Now a harness watch logs it.
* `Load` not popping the directory stack was hidden by my own harness, which reset the stack between the sides.

Three were equivalent and were dropped, each with its reason in the suite: the group check in `GetNames` (the group's name is at offset 0, so null reaches `AtCopyName8` as a null source, which writes the same empty name), and each `Load`'s `file.Close()` (the destructor does the same at the end of the same scope, with nothing between).

Limits:

* The concrete classes are the harness's on both sides, so this says nothing of how a bank plays. `CreateBank` here makes a bank unless the name begins with N.
* The loader at the owner's +0x0C is a double; only its slots 2 and 3 are known.
* Slots 3 to 9 of the bank are never called, and their arguments are unknown. Slot 14 is the harness's.
* An empty segment name is not run through a database: the hash reads a byte past the terminator, so the slot depends on stack bytes, in the original too. An empty bank name is run, because it is not inserted.
* Directory paths too long for the buffer are not run, because the buffer would be uninitialised on both sides.
* Bytes after a terminator in a name are stack garbage, so names are compared as strings.
* Counts that are negative or above the pool of 1,024 segments are not run.

`python -I tools/verify.py`: 40 functions by the host compiler: 8 MATCH, 2 MISMATCH, 30 SIZE; none MISSING or UNRESOLVED. The 4 vftables MATCH.

## Host test

`tests/native/test_aob.cpp` on x64, Release: passes. It reads every kind of word through the real text tokenizer and covers sharing, the loader, users, lengths and clearing.

Its first version crashed. It called `Find` on a cleared map, whose size is zero, and the hash divides by the size. The original does the same, so the test now checks `m_entries` instead. Anything calling `Find` on a cleared map divides by zero on this hardware and on the Xbox alike.
