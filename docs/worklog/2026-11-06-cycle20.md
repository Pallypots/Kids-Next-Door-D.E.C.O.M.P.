## Findings

* Copying a database can run past its lists. See docs/portability.md.
* An `Init` over a table that exists calls the virtual `Clear`, which resets what `Allocate` has just set. Once a count of zero leaves a table behind, later `Allocate` calls on that object keep a count of zero. Kept.
* `CopyFrom` inserts no names, so a copy finds nothing by name.

## Mistakes and fixes

* Heap corruption on real files turned out to be the overrun above. The test heap is now padded and the overrun compared.
* The check that a mutant was recompiled looked only at the last attempt's log, so a link retry looked like a stale build. It stopped the run rather than giving a wrong verdict. Fixed.
* Eight mutants survived at first. My allocation sequence got stuck at a count of zero, which hid four; textures and shaders held the same values; nothing compared a new object; nothing saw when a database joined its group. One, not closing the file, was equivalent and is dropped.
* The first run of the mat suite after this work did not compile: a local variable hid a helper. Found by running the suite, before any commit.
