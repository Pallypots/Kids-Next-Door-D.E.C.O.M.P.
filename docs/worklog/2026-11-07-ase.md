# Particle emitters, .ASE

Subsystem `at/ase`. Task: the loader at 0x0003F760, and what it alone needs. State: Semantic-tested. No original compiler here: a host MATCH says nothing about it.

## The format

Text, in the engine's own tokens: `Emitter[n] { Emitter "name" { word values ... } ... }`, with an optional `NameSpace "x"` first. It has nothing to do with 3D Studio's ASE, despite the extension. 221 files on the disc hold 364 emitters between them. The 47 words are at 0x002B1F20; `ParticleRotationSpeed` sits out of the order of its id there, and the table keeps it so.

Words the real files use: DeltaInitialSpeed, DiffuseColor, EmissionCone, EmissionConeInnerAngle, EmissionConeScale, EmissionEventChance, EmissionLine, EmissionPoint, EmissionRectangle, EmitterLifetime, LinearColorChange, LinearColorChangeKeys, LinearMotionBlurKeys, LinearRectChange, LinearSquareSizeKeys, LineSegIntersectTesting, LocalAcceleration, LocalBoundingSphere, MatAssignment, MaxEmissionEventRate, MaxParticles, MaxParticlesPerEvent, MotionBlur, ParticleChance, ParticleInitialSpeed, ParticleLifetime, ParticleRotationSpeed, QuadraticColorChangeKeys, QuadraticMotionBlurKeys, QuadraticRectSizeKeys, QuadraticSquareSizeKeys, RectWidthHeight, SquareSize. The rest are reached only by written text.

## What a real build does on real files

Every .ASE file loads through recovered code, with no seam reached. Nothing on the path stands in, other than the heap and report helpers every oracle redirects. That includes the 87 emitters with LineSegIntersectTesting, which make a pool of queries at the end of their body.

What a build does not do: nothing uses an emitter. Making, updating and drawing particles are not recovered, so the data is held and goes no further. AtQueryPool's and AtSegmentQueryPool's slots 2 and 3 (TakeNext, Update) stop with a diagnostic, and slots 5 up are not declared; nothing in the loader calls them. Nor is the owner that calls this loader, 0x0002EED0 with 0x0002E7C0, recovered.

## Quirks kept

* A second read of one emitter empties its list and pool and resets it. Reset does not touch the keys only a word fills: end, middle and their times stay from the first read.
* Square size keys use one curve for width and height, taken from the width's keys, and divide by way of an inverse, `x * (1 / t)`, where every other curve divides by `t`. Not always the same bits.
* In a motion blur's curves the second start, y's, is kept in a register unrounded, while the other three are stored as floats.
* The cross product at 0x00050790 tests its length against exactly 0, unlike AtVector3::Normalize's 5e-6. Its z stays unrounded in the length.
* Normalizing the direction at the end can only make x and y exactly 0 for a direction along z. A rate of 0 or below is reported, and if the report returned goes on to divide. A count of 0 materials or blurs likewise.
* LineSegIntersectTesting is acted on at the end of the body, so MaxParticles may follow it in the text.
* The word before the count is taken on trust, as for lens flares.
* AtQuery::Reset leaves the word at +0x7C alone, and ~AtQueryPool runs Release a second time with the base's Free, finding nothing.
* AtEmitter has a cookie of 0x10 in its array, where the rest of the engine's have 4. `alignas(16)` gives that on the host. What in the original made it so aligned is not known.

## Arithmetic

Stores are `float`, register values `double`, as in at/AtVector3.h. One real difference from that rule: the original takes fsin of the C library's acos, 0x00126600, in the x87's full 64 bits. A double's pi gives the wrong answer at a cosine of -1, by sign as well as size: the original's fsin of 64-bit pi is exactly -2^-64. So the source has `SineOfAcos`, sqrt(1 - c^2) with that one case apart. The original's sine is in 64 bits where this is in 53, so a difference is possible after rounding to float, about one case in 2^29. None appeared in 30,000 direct cases or on any file.

## Verification

`tests/oracle/oracle_ase.cpp`. Compared: every word of every emitter from +0x0C up, its list, the pool and every query in it, with pointers as offsets; the call log; messages; crashes.

* All 221 real files, four ways: fresh, over itself, after clear, into the deleting form.
* Written text: each word alone on two fills; every ordered pair of words; values at each boundary; error text. A check that each word changes an emitter from an empty body found 45 of 45 do.
* Direct: an emitter's reader with text that ends in the body, on a tokenizer whose Error stops it. Each helper on made-up values, by 3,000 to 30,000 cases.
* Pools and queries on their own, on each of the heap's fills, for counts of 0, 1 and 3 and of 0, 1, 2 and 5 to a query; no room; no heap.

* Six inputs, searched for offline, on which dividing by a time and multiplying by its inverse round to different floats, plus one for the quadratic path. Random values would not find them: that first left two mutants alive.

Result: `NO DIFFERENCE OBSERVED: files ASE 221, 1456 emitter comparisons in files, 9377 in written text; 7642005 comparisons, 0 differences`; entries reached 49 / 49; mutants detected 359 / 359. Every other suite still passes with no mutants, and 23 of 23 host tests pass on x64.

The first mutant run left nine alive. Eight were gaps, now closed: the two above; a cone matrix store of 0 that Reset hid; a second read with the same text, which hid both its Release and its Reset; storage at +0x90, which the query comparison skipped; the base's Free called only through Release; and word +0x18, already zero before Init. The ninth is dropped as equivalent, with the reason in the suite.

What it does not show:

* An empty emitter name is not compared. The map's hash reads the name's second byte anyway, which is whatever was on the stack. Its slot differed between sides, as it may in the game.
* A NaN's sign is not compared: x87 and the host may differ in it.
* Counts large enough to overflow the size of an array are not compared. The original's multiplication wraps, and modern `new[]` does not.
* No real path reaches AtQueryPool::Allocate or AtQuery's owned storage. They are compared by calling them directly.
* A vector branch of 0x0002E880 is not reached by anything recovered: it would need an array of databases, made by 0x0002E7C0.
* Text that ends inside a body through the file code never returns, in either side, unless the report stops: compared only through the direct tokenizer.

## Shared edits and overlaps

* `AtNameTableOwner`: `m_unknown108[0x3C]` split into `m_emitters` (+0x108) and `m_emitterSpaces` (+0x120), with `AddEmitters`, 0x00040030. Nothing used the old name.
* `AtVector3::SetCrossNormalized`, 0x00050790, defined in src/at/AtEmitter.cpp. It has 40 callers elsewhere, so it may want moving to AtVector3.cpp at integration.
* `AtSceneSphere` used for both the emitter's and the pool's sphere. I first wrote a new class, and the record's duplicate check caught it.
* 0x00035820, set to (0, 0, 0, 1), belongs to the `particle` key. `SetIdentity` in src/at/AtEmitter.cpp stands in, and is not recorded. Replace it when that merges.
* `AtQueryPool` and friends may be what the `particle` work knows by another name: 0x000552B0, 0x00055520 and 0x00057B50 in its list are neighbours. Its keys may also want 0x0017AED0's class, and 0x00057B90's other callers 0x0004EC15, 0x001301A1 and 0x00202465 make these queries too.
* 0x00057950's other caller, 0x001305A3, uses the pool from elsewhere.
