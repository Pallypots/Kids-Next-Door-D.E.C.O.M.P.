# The AtAp layers below the atlas layer: start-ups, App's configs, and the event, network and I/O layers (subsystems `gm/atap`, `at/atap`), 2026-11-08

For the integrator: this holds what belongs in docs/startup.md, docs/STATE.md and docs/verification.md. Reference build knd-xbox-usa-5454008a-v1. State of
everything here: Semantic-tested. A host MATCH from `tools/verify.py` says nothing about the original compiler (blocked, docs/toolchain.md).

**What a green result does not show, first.** In the oracle the fourteen start-ups run against tables of doubles for App's vftable and for every layer
object's vftable: the chain is shown to call the same slots on the same objects with the same arguments and configs, and nothing more. No layer object's
Init runs inside the chain there. The event, network and I/O objects' Inits are checked apart, each on its own; the factory's device and file systems are
doubles on both sides (the Xbox's are not recovered). The real chain, layers and memory system running together, is exercised only by the host tests.

## Where a real build stops now

`test_app C:\KND\analysis-local\levels` (app.ini and `JamFiles\XBox\AppInit.JAM`), and `test_app` with no directory, both on x64:

    main stopped: App start-up: the math layer's Init (0x000B38D0) is not recovered
    memory reported: 4294967295 total, 0 overhead; I/O context: 6 file systems, 8 buffer blocks of 32768 bytes

GmApp's start-up now gets its memory figures from the host (port code, platform/host_sdk.cpp; this machine has more than 4 GB free, so both 32-bit fields
are capped). The AtAp chain then brings up, in order: the memory system over a host region with App's four heaps (35 127 296 bytes); the event layer and
its heaps; the network layer, which turns itself off whatever App asks; the I/O layer: every I/O heap, the factory, App's AtIoContext at +0x31C (a stack
of 6 file systems, 16 namespaces, the host's device, a read buffer of 8 blocks of 0x8000) and it becomes `AtIoContext::s_instance`. The next layer up, math
(App+0x384, vftable 0x002847FC), is the first whose object is not recovered, and start-up stops at its Init. No disc file is read before it: App.ini is
read later in Init. What stops after it, if each layer's Init were supplied (`test_atap` runs the chain with stand-ins to check this): data management,
script, kinematics, graphics, controller, sound, video, scene Inits, then the user interface layer's config (App slot 56, 0x0008DB30, needs the material
owner's slot 15), its Init, then the atlas layer and the rest of App::Init as the App worklog lists.

`NO DIFFERENCE OBSERVED: 82 start-up chains, 6 crashes on both sides; 1584172 comparisons, 0 differences`; entries reached: 23 / 23 (atap), 49 / 49
(atap_at); `--mutate` fails as it must. Mutants: **114 / 114** (atap) and **186 / 186** (atap_at) detected. The first atap_at run left eight survivors:
three were raises on allocation failure, which no case reached (now run: requests fail after a push of the context's or the buffer's heap, and both
sides crash alike after the raise: the 6 crashes); five were equivalent and are dropped, each with its reason, in tests/oracle/suites/atap_at.py. The atap
mutants ran before the out-of-memory cases were added to the harness; the gm source did not change after. Every suite, run with no mutants after the
shared edits: 40 suites, no difference, every entry reached.

Cases. The chain: each of the fourteen start-ups entered on its own; every running flag (and the memory system's) set alone to 1 and to 2 (bit tests against
non-zero tests); 40 random entries with random flags. Each config double first hashes what it was handed (the start-up must have cleared it), then fills it
with a pattern that the next Init double hashes. App's configs: each on garbage, with heaps present and one missing, and the 64 words around compared.
Globals: each constructor on a filled buffer; Save and Restore with globals set, cleared and partly cleared. Setters: each of the thirteen; the five

BlockSize, MinimumBlocks, AtIoGetFactory. Buffer: Init over six block sizes and minimums by ten byte counts, again on top of itself, then Clear;

## Quirks of the original, kept

* The network layer writes 0 into its config's first word before reading it: the network is never brought up, whatever App's slot 11 says.
* The I/O layer applies its two defaults (stack 1, spaces 8) twice, before and after it starts the factory; the second time as `< 1`.
* AtIoGetFactory puts the saved globals back before starting the factory and saves them again after; the factory's Init is handed a byte it never reads.
* AtIoSetDeviceHeaps ends by setting every I/O heap again (0x00102F40), all but 0x00083490's.
* AtIoContext::Clear clears three of the four context pointers Init set; 0x002C6328 is left.
* AtIoBuffer::Init tests one byte of its flags and stores a whole word.
* The graphics start-up clears its config twice (0xD4 bytes, then 0xF0); App's I/O config slot alone does not clear the config.
* App's slot 56 initialises the event layer's names again, with 16 and 16, long after the event layer did.
