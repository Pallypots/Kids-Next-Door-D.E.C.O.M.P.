## What the machine is

The scripts of an .AFA (worklog 2026-11-08-aft) are Flash action bytecode, run one block at a time by `AtFpActionScriptVM::Run` (0x0001F020) on a stack of 30 values.

```
instruction   u16 code; from 0x80 on, u16 length and that many bytes of data. Little-endian, unaligned.
Run           from instruction 0 until an End (code 0) or a Call (0x9E) whose ExecuteScripts returns not 0. Nothing else bounds it.
Jump / If     u16 target, an instruction index (not a byte offset): taken only if below the block's m_read; If by the popped value's integer.
Push          a list of (u16 kind, value): 0 a C string, 1 a float, 7 an int, 0x20 eight characters naming a string of the .AIS. Any other kind, or a name not found, never steps on: the loop does not end.
GetURL2       method & ~3: 0 and 0x40 load a movie (LoadMovie), 0x80 and 0xC0 a remote function call ("RFC") into game code, named by the URL, with what the target resolves to; any other is reported.
```

Dispatched codes, by the SWF numbering: 0x04 NextFrame, 0x05 PreviousFrame, 0x06 Play, 0x07 Stop, 0x09 StopSounds, 0x0A Add, 0x0B Subtract, 0x0C Multiply, 0x0D Divide, 0x0E Equals, 0x0F Less, 0x10 And, 0x11 Or, 0x12 Not,
0x13 StringEquals, 0x14 StringLength, 0x15 StringExtract, 0x17 Pop, 0x18 ToInteger, 0x1C GetVariable, 0x1D SetVariable, 0x20 SetTarget2, 0x21 StringAdd, 0x22 GetProperty, 0x23 SetProperty, 0x24 CloneSprite,
0x25 RemoveSprite, 0x26 Trace, 0x29 StringLess, 0x30 RandomNumber, 0x32 CharToAscii, 0x33 AsciiToChar, 0x34 GetTime, 0x81 GotoFrame, 0x83 GetURL, 0x8B SetTarget, 0x8C GotoLabel, 0x8D WaitForFrame2, 0x96 Push,
0x99 Jump, 0x9A GetURL2, 0x9D If, 0x9E Call, 0x9F GotoFrame2. Every other code does nothing.

**The 20 real .AFA use 28 codes**: 0x00, 0x06, 0x07, 0x0A, 0x0B, 0x0C, 0x0D, 0x0E, 0x0F, 0x12, 0x13, 0x14, 0x15, 0x17, 0x1C, 0x1D, 0x20, 0x21, 0x23, 0x81, 0x83, 0x8B, 0x8C, 0x96, 0x99, 0x9A, 0x9D, 0x9F
(Push 6787, GetVariable 3507, SetVariable 1496, If 1375; Push kinds 0x20 4767, 0 1262, 7 727, 1 31; GetURL2 methods 0xC2 242, 0xC0 3, 0 7; 29 backward Jumps). **All 44 dispatched codes are recovered**; the 16 the real
scripts do not use (0x04, 0x05, 0x09, 0x10, 0x11, 0x18, 0x22, 0x24, 0x25, 0x26, 0x29, 0x30, 0x32, 0x33, 0x34, 0x8D, 0x9E) rest on written scripts.

A value (0x2C bytes) is text (type 0), a real (1), undefined (3) or an integer (7), and caches its other forms with three flags, one per pair of forms (+0x18 text and integer, +0x1C text and real, +0x20 integer and
real). Each handler pops into values of its own, `AtFpActionScriptLocalValue` (0x12C bytes, vftable 0x00274878), which keep text under 0xFF bytes in a buffer they carry.

## What it calls out to, not recovered (include/at/AtFpDisplay.h, src/at/AtFpDisplaySeams.cpp)

Each stops with a diagnostic in a real build:

* `AtFpDisplayManager`, at the application's +0x004: GetCurrentFrame 0x0002BF50, GotoFrame 0x0002B970, SetPlaying 0x0002BFC0, StopSounds 0x0002BF20, GotoFrameByLabel 0x0002BF80, GotoFrameByExpression 0x0002CB70,
  SetTarget 0x0002C3B0, LoadMovie 0x0002CFD0, ResolveTarget 0x0002CC90, GetVariable 0x0002C9C0, SetVariable 0x0002CAA0, GetProperty 0x0002C320, SetProperty 0x0002C360, ExecuteScripts(int) 0x0002C150 and
  ExecuteScripts(const char*) 0x0002C1C0. The machine reads its context stack (+0x38, 50 entries of context and target, count at +0x194) itself.
* `AtFpDisplayMgrContextStack::SetTarget` 0x00016130.
* `AtFpRfcTable::Call` 0x0002D9E0, at the application's +0x264: a remote function call into game code, reporting "RFC %s not defined" for a name it lacks. `AtFpRfcArgs` (0x3C bytes): 0x00021620, 0x00021AD0,
  0x000216E0, 0x00021DD0, 0x00021680, only for Trace. Its constructor and destructor are declared as named calls (Construct, Destruct) so that the harness can stand in for them.
* The clock, 0x00020640: the existing `AtPlatformMilliseconds` (include/gm/GmManifestLoader.h names it for the same address).

So in a real build every frame, label, target, variable, property, movie and remote call stops at its seam: of the real scripts' codes only arithmetic, comparison, strings, Push, Pop, Jump and If run without one.
A real script reaches GetVariable within its first instructions, nearly always.

## What the green result does not show

* **Doubles stand in for everything the machine calls out to**, the same on both sides, each call logged with its arguments and the stack as it stands: the display manager (with a table of variables per side: what
  a script sets it gets back; a name never set gets a value chosen by the name's hash), the context stack, the remote calls and Trace's arguments, and the clock. So what a real variable holds, what a real
  GetProperty returns and what ExecuteScripts does are not known here; only that both machines ask for and do the same with what they are given.
* **Step by step means**: the block whole, and the block once for each instruction with that instruction made an End, each from a fresh start, both machines compared field by field after each; plus every call
  out, with the stack at that moment. The state between two call outs within one run is not compared otherwise.
* **Not run**: a Push of an unknown kind, or of a string id not in the .AIS: both loop forever without a call out, and a harness cannot stop them. A Jump to itself, the same. A loop with call outs is stopped on both
  sides at the same call by a budget of calls (4000; 300 in its written case), compared up to there.
* **Crash cases, compared up to the crash**: RandomNumber with a limit of 0 (an integer divide fault, both sides), each allocation failing in turn (reported, then written through), the general heap missing.
* **LoadMovie with a name of 0x44 characters or more**: the original writes its zero past its 0x40-byte buffer, into its own frame. The recovered code does not write past it. The written case of 0x43 characters is the
  longest compared.
* The C library: atof is given only the decimal form the original's accepts (TextToReal), and "%g" is written out by `AtFormatGeneral` (src/at/AtFlashScriptHost.cpp), both compared with the original's over 20,000
  random numeric strings and 200,000 random real bit patterns, every special value among them. atoi is the shared `AtNarrowToInt`.

## Quirks of the original, kept

* Run has no bound but the End; Jump and If go by instruction index and are ignored at or past m_read; If tests the popped value's integer, so 0.5 is false.
* A stack of 30 holds 30; a push to a full stack does nothing and returns 0, and a block given to PushString is then leaked. A pop from an empty stack leaves the handler's value undefined.
* A real is pushed as an integer when integral (SetReal). Its integer is the original's `_ftol`: truncated to 64 bits, then the low 32, so 3e9 gives 0xB2D05E00 and a NaN or anything past 2^63 gives 0.
* A real's text is "%g" with the original library's three-digit exponent ("3e+009") and its 17-digit, half-up rounding; infinity is "1.#INF", the default NaN "-1.#IND".
* IsInteger is true for undefined, for the empty text, "-" and any run of digits with one leading '-'.
* WaitForFrame2 pops and ignores its skip count; CloneSprite and RemoveSprite pop and convert their operands and do nothing else.
* StringExtract counts from 1, takes index 0 as 1, and cannot start at the last character (the index must be below the length, signed). StringAdd makes room by the two capacities, not the lengths.
* CharToAscii sign-extends the first character. StringEquals and StringLess, CharToAscii, StringLength and StringAdd push undefined for an undefined operand.
* SetTarget with a string id not found goes on as undefined and sets the target to ""; GotoLabel with one not found does nothing. An empty path sets the current context's target.
* LoadMovie drops the last four characters of its name and reports a name of one to four characters, then loads it anyway.
* RandomNumber draws four words of the table, 7+8+8+8 bits, and divides unsigned: a negative limit is a huge one.
* A handler's own value takes its blocks from AtIoTokenFile::s_heap (0x002C60B0), never its m_heap; asked for exactly 0xFF while in its buffer it keeps its capacity.
* The text of undefined, and the empty text StringExtract pushes, are pointers the original keeps in data (0x002B03C8, 0x00270F0B); GetURL2's mask is a word at 0x002B0344. Nothing writes them.

* `include/at/AtFlashShape.h`: `AtFlashApplication` gains `m_display` (AtFpDisplayManager, +0x004, its known 0x1D0 bytes) and `m_rfc` (+0x264); `m_unknown000` shrinks to 4 bytes with `m_unknown1D4` after the display

* `include/at/AtFlashScript.h`: `AtFpActionScriptValue`'s +0x10 to +0x20 are unions, so that each keeps its old name (`m_unknown10` and so on, which the aft suite's mutants use) and gains one saying what it is
  (`m_int`, `m_real` as float, `m_haveTextInt`, `m_haveTextReal`, `m_haveIntReal`). The value, stack and machine gain the methods above, and the header gains `AtFpActionScriptLocalValue`.
* Nothing renamed.

## My mistakes

* Truncate first followed the x87 integer indefinite (0x80000000). The original's `_ftol` (0x001260BC) works in 64 bits; the oracle's direct tests showed it at once.
* The oracle logged the archive's file reads (done outside the comparison) on one side, and freed the harness's own strings while logging was on, which only the recovered side's operator delete logs; both
  read as differences until fixed.
* The first mutant run had 13 survivors, 7 of them gaps in my own harness.
* The written scripts' holder let `AtFpScript`'s destructor free the harness's own arrays: a heap corruption, found with `--trace`.
* A host test expected a stack of 30 to hold 29.
* A Python patch lost its backslashes, as the brief warns; fixed with the edit tool.
