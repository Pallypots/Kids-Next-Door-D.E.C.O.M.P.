# The AGN family of loaders: subsystem at/agn

Started 2026-11-07. State of this work: Semantic-tested. Nothing here is a byte match; a host MATCH from `tools/verify.py` is not a claim about the original compiler.

## What each extension holds, from the code and the keyword tables

| Ext | Loader | Holds | Real files |
| --- | --- | --- | --- |
| .AGN | 0x00027D50 | Named lists of materials, `MatAssignment` / `MatAssignmentWithNameSpace` | 61 |
| .AGA | 0x00028340 | Material animations: `FrameNumber`, `MaterialKey`, `MatAnimation` with `Keyframes`, `Rate`, `Length`, `LoopPeriod` | 7 |
| .AGI | 0x00029DC0 | Images: `MatAssignment`, `Image` | 102 |
| .AGF | 0x0002A290 | Fonts: `Font[n]`, `MatAssignment`, `Font2D`; `Font3D` stops with a message | 2 |
| .AGL | 0x0002AC10 | Lights: colours, `Range`, `Attenuation`, cone angles | 17 |
| .ASL | 0x0003FAC0 | Lens flares, by its keyword table. **No file on the disc is this.** | 0 of that format |

The three disc files named .ASL are in `DESIGN\BEHAVIOR` and begin with binary and names such as `func0000`: compiled scripts of some kind, not recovered here and not established further. Run through 0x0003FAC0 they are read as bad text, and the oracle compares that, which shows little. So the lens flare's fields are tested by written text only.

## Owner classes

0x00025F70-0x000260F0 are `AtMaterialOwner`'s add methods, as suspected: lights +0x168/+0x180, lists +0x1A4/+0x1BC, animations +0x1E0/+0x1F8, fonts +0x258/+0x270, images +0x294/+0x2AC. 0x00040070 is on `AtNameTableOwner` instead, +0x144/+0x15C, and tests only for null, as `AddScene` does. A flare looks its materials up on the name table owner's object at +4, using `AtMaterialOwner`'s offsets: that object is typed `AtSceneDevice*` in `AtNameTableOwner`, so `AtSceneDevice` and `AtMaterialOwner` may be one class. Not settled; the code casts.

## What stands in for the original

Images, fonts and lights are made by the graphics layer. Harness items stand in on both sides. An image's body (0x000586A0, in a range another agent holds) and a font's (0x000415A0 with 0x000FEA90 onward, not in budget) are not recovered: the harness item only walks tokens and logs them. So on .AGI and .AGF this shows the databases, their material lists and the order of calls agree; it does not show anything about what an image or font makes of its words. A real build has no concrete image or font class, and these bodies do not exist in it. A light's body is real on both sides.

## Quirks of the original, kept

* `.AGN`'s Load, not Read, empties and sets the keywords, unlike its siblings. Read called directly needs keywords set.
* A list of zero leaves its block until the destructor or a later read that finds a nonzero count, since reads free on the count and the destructor on the pointer.
* `.AGI` and `.AGF` Load note the file system, then Read can clear it (through `Clear`, or `Init`'s virtual Clear when a table is left), and Load's pop then goes through null. So loading over a database with a table, or a second `Image` word in one file, crashes in the original. Both sides crash the same in the oracle, which guards every load, and counts them (170 in a run, all from loading a second time on purpose or those written texts).
* Text that ends inside a light's, flare's, square's or run's body loops on the report for ever, unless the report stops. The harness has a watchdog, for mutants that bring this about.
* A second `MaterialKey` or `MatAnimation` in .AGA is reported, read over, and leaks.
* `.ASL` takes the word before the count on trust. Its own NameSpace test passes an empty name as a space with an empty name.
* An animation's `Length` sets the loop period to one more than itself only when none is yet given. A `LoopPeriod` under Length is reported only if Length came first.
* `AtGrKeySet`'s destructor makes a call through its vftable if a count remains: the pure call. Its one derived class leaves none.
* `AtGrFrameNumberSet::Free` frees with no null test; `Find` takes a length it does not use.
* Three deleting destructors are vector-deleting (0x0001A070, 0x0001A190, 0x0002E9A0), from an array of these databases somewhere not recovered. The array branch is compiler-made and not compared; on the host the same slot is the scalar form.

## Not compared

* Names that are not strings, where a name is required: `ExpectName` leaves uninitialised stack on both sides.
* Bytes past a short name's terminator, for the same reason.
* An empty name that is searched for, as a .AGA key's is (lists test for it first and do not search). `GmNameMap::HashOf` on an empty name reads its second byte, uninitialised stack, so the search finds or misses by chance. A written case with the empty name in the maps did differ for this reason, and was removed: the difference is the stack's. The list's test for empty is shown against a map with the empty name in every slot.
* NaN's sign in `Interpolate` when a run's span is zero: x87 and the host may differ.
* The frame set's word 0x4B is tested through a keyword table of the harness: in no table of this family. It is in the tables of .AGO or .AGH, which share 0x00034F90, not recovered here.

## Not recovered

* AGV and AGP, 0x0002B430-0x0002B8B4: left out on budget, and the text case index has no file of either, so no real process text is available to the ags suite through them from these cases. Their shape is the same as AGL's, with a concrete process in the graphics layer.
* The image and font bodies above; drawing a flare, 0x00052350-0x00052CB6; a light's other methods; the frame set's siblings from 0x000350E0.
* Over budget: 85 functions and 8 vftables against about 60. They are small and one pattern. Say so rather than hide it.
